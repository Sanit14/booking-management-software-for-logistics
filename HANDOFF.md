## For the next session to know
1. `memoSettlement` has no SQL twin: SQL reads `frozen_net_paise` / `round_rupees`. A new step goes in `keeper/memoSettlement.ts` with a test, in `memoDetails.ts` (`settlementLines`) and in the print block (`keeper/print.ts`, `print/memo.ts`); the card's lines and the window's come from the same function.
2. The memo sums add `SUM(wasuli_paise)` in `memos.ts` only; `lrSql.ts` (freight, hamali, total) is unchanged. A new money column on `lrs` still goes in `lrSql.ts` + `lrAmounts` with a case in `lrSql.dbtest.ts`.
3. `Dialog` has a `noActions` prop (no Cancel / Confirm row: the children carry their own buttons, as `DetailsWindow` does).
4. Same as 4.4 / 4.5: `npm run measure:ui` and `node scripts/test-installer.cjs` are not part of `npm run check`; `npm run check` can fail by chance when the PC is busy; a fresh worktree needs `npm ci` and `npm run postinstall` (about 6 minutes; the native rebuild needs the short-path rule in the decisions).
5. Driving the real window: `npm run build`, then `electron . --remote-debugging-port=9222` with `BM_DATA_ROOT` / `BM_BACKUP_DIR` on a throwaway folder, then Chrome DevTools Protocol from Node 20 with `--experimental-websocket`; a window behind others needs `Page.bringToFront` + `Emulation.setFocusEmulationEnabled` before `captureScreenshot`; the native Print dialog is a window titled "Print" of the same process (Esc closes it).
