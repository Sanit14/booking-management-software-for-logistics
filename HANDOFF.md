## For the next session to know
1. `Dialog.tsx` is the one place Escape is handled for dialogs: it ignores a `cancel` that is not its own (React bubbles `onCancel` through the component tree, the browser does not). A new dialog nested in another needs nothing.
2. `npm run test:electron` now also builds `src/ui/dialogHarness.tsx` with Vite (`scripts/test-electron.cjs`, Node 20; Vite cannot run inside Electron 22) into a temp folder, and `electron/dialog.electrontest.ts` drives it with real key events (`sendInputEvent`; the window is shown inactive, a hidden one gets no keys). Add a nested-dialog case to the harness when another one misbehaves.
3. The memo's sheet numbers are `FIRST_ROWS`, `NEXT_ROWS`, `TOTALS_ROWS`, `SETTLEMENT_ROWS` and `WIDTHS` in `print/memo.ts`; the real-PDF test (`cutMemoCells`, `noOverrun`) decides what fits. The statement and the reports pass their own capacities to `paginate` and are unchanged.
4. `isBookingStation` (`keeper/masters.ts`) finds the station by name key, as `lrs.defaults` does; a test that must close Yavatmal does it in the file (SQL), as `lrs.dbtest.ts` does.
5. The wire field is `qty` (not `articles`) in `MemoSettlement` / `PrintSettlement`; `print/captions.test.ts` fails if "article" or a removed caption key comes back in `src/`, `shared/` or `print/`.
6. Same as 4.4 – 4.7: `npm run measure:ui` and `node scripts/test-installer.cjs` are not part of `npm run check`; a fresh worktree needs `npm ci` (it runs the postinstall rebuild; about 10 minutes here); the Stop hook checks the MAIN folder.
7. Driving the real window, what was new this time: for a real OS-level key, ask computer use for the exact `electron.exe` of the worktree (the dev app is not "Booking Manager" to Windows) and click the app once before the key. Do **not** use `open_application`: it starts a new, empty default Electron window. A window that Windows hides (minimised, occluded) stops painting and screenshots go stale: restore it with `ShowWindowAsync` (user32) from PowerShell. Closing the app does not free port 9222: the detached keeper inherited it; shut the keeper down (`POST /shutdown`) before starting the app again, or it is not debuggable. `Page.captureScreenshot` over the port shows the page even when the OS screenshot is stale.
