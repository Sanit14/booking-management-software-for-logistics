## For the next session to know
1. `ensureBookingStation` runs in `becomeReady`, so a new book's guard baseline is 1 row; a test that needs an empty book must delete the station (`sql()` in `keeper/server.test.ts` does it under Electron's Node).
2. The pending filters are built in `keeper/memos.ts` from `filterParts` (AND between filters, OR inside; a name is a firm id or an exact walk-in text, each half FALSE rather than NULL for the other kind). The station list and the name search skip their own filter; the name search also leaves this side's picks out.
3. `PendingPicker` owns the picks and tells the page through `onPicked`; ticks live in the caller. `DetailsWindow` gets the truck boxes as a `header` node and a `precheck`; the boxes' text lives in `LoadingMemoPage` so it survives Esc.
4. The memo paper's widths are in `print/memo.ts` (`WIDTHS`); the real-PDF test decides what fits (`cutMemoCells`). Hamali and Total per row come from `lrAmounts`, the totals row from the frozen figures.
5. Same as 4.4 – 4.6: `npm run measure:ui` and `node scripts/test-installer.cjs` are not part of `npm run check`; a fresh worktree needs `npm ci` and `npm run postinstall` (about 5 minutes); the Stop hook checks the MAIN folder.
6. Driving the real window: start the app detached (`Start-Process` with `--remote-debugging-port=9222`, `BM_DATA_ROOT` / `BM_BACKUP_DIR` on a throwaway folder), then Chrome DevTools Protocol from Node 20 with `--experimental-websocket`; use `Emulation.setDeviceMetricsOverride` for the size; the native Print window is titled "Print" (find it with EnumWindows, Esc closes it); a second app on port 9222 is silently not debuggable, so close the first one.
