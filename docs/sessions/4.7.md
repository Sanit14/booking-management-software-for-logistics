# Session 4.7 — DM's sidebar and Settings, captions out, the new memo in two steps, the memo print like DM

## Goal
Make BM feel like DM for the clerks' muscle memory, and make the loading memo simple. The sidebar and Settings follow
DM's order, explanation text goes, the new memo becomes "list + filters → Next → Memo details", and the memo print gets
DM's columns. Mockups: https://claude.ai/artifact/TEHZ8T2aW9WdWYVJnA6J4M — boards **Sidebar + Settings**,
**New memo — option A (CHOSEN)**, **Step 2 — Memo details**, **Memo print — DM columns**. 4.6 is merged (`80f7d26`,
0.5.0, `KEEPER_VERSION` 22, schema v5). The pilot moves to **4.8**.

## Decided (owner, 2026-11-13)
**1. Sidebar = DM's order** (BM's type sizes stay).
- Brand as DM: orange logo box, "Sundeep Freight Movers", "Yavatmal".
- **Quick LR (F2) stays where it is**, under the brand.
- **MAIN:** Dashboard · LR Entry · Loading Memo · **Saved Memos** · **Wasuli**.
- **ADMIN:** Firm Accounts · Reports · **Master Data** · History · Settings.
- Changes from today: Saved Memos becomes its own page (no more New / Saved tabs), Wasuli moves up to MAIN, and
  "Masters" is renamed "Master Data" everywhere.
- Badges are counts only. Loading Memo = pending LRs; Saved Memos = memos saved today; Wasuli = unassigned wasuli
  (only if the existing summary query can give it with one more COUNT, otherwise no badge).
- **Foot:** one line with the seat and the last backup (red when failing or lost), then "Booking Manager v0.6.0".

**2. Settings = DM's single column** (max width about 720 px). Sections, top to bottom:
1. **This Computer:** computer name, Save.
2. **Data & Backups:** one status line ("Backed up today 14:00 · 11.1 MB", red when failing); Save a copy… and
   Restore… (Admin PIN); data folder; backup folder with Change….
3. **Software update** (ADMIN ONLY chip): this version, then Check for update.
4. **PINs** (ADMIN ONLY chip): Change System PIN, Change Admin PIN.
- Each section header is an orange icon plus the title. A protected button names its PIN ("Restore… · Admin PIN").
- **Keyboard shortcuts leave Settings:** a **Shortcuts** button on the LR Entry page header opens the same list (Change,
  Reset to defaults) in a dialog.
- **The LR defaults card and the Company card leave Settings, and both values are fixed in the app:**
  - **From** on every new LR is **Yavatmal**. The keeper makes sure that station exists in the master and is the
    booking station.
  - **The print header lines** are constants (see Rules). Their keeper routes, the Settings code behind them and their
    strings are deleted. History still reads old `settings.lr-defaults` / `settings.company` rows.

**3. Captions out, across the whole app.**
- **Keep:** numbers and facts (Next: 5122 · On loading memo 1482 · 19 pending · Next challan 1483); errors and
  refusals; warnings before something that cannot be undone (cancel memo, restore, backup folder on the same drive,
  discard a typed LR); the first-run PIN setup, the recovery code and recovery text; "These look like…" lists.
- **Remove:** how-to and "what this does" text:
  - `memo.stationHint`, `details.roundHint`, `escHint`, `editEscHint`, `editNote`, `noneText` (becomes the short title
    "No details of report yet")
  - firm `openHint`, `growthNote`, the reports `openHint`s, `firmNote`, `lrsOpenHint`
  - wasuli `amountHint`, `remarkHint`
  - `backupText`, `dataFolderNote`, `backupFolderText`, `seatText`, `seatNameHint` (becomes the input's placeholder),
    `restoreText`, update `text`, pins `cardText`, `companyCard.text`
  - masters `firmStationHint`, `phoneHint`; LR `dateHint`; memo `note` ("If another seat loads…"); search `hint`
  - every line saying a field is optional
- Tooltips may keep a key's name ("Quick LR (F2)").

**4. Loading Memo = New memo only (mockup option A).**
- **Left:** pending LRs, oldest first. Columns: tick · LR · Consignor · Consignee · To · Qty · To pay · Paid. Space ticks
  a row, Ctrl+A ticks all shown, plus an Untick button.
- **Right column:**
  - The filters in use, as chips on top (× removes one, Clear removes all).
  - **To station:** a tick list of the stations that have pending LRs, with counts.
  - **Consignor** and **Consignee:** each a **search box**. Typing shows **at most 5** names that have pending LRs
    matching the other filters, busiest first, with counts, plus "and N more · keep typing". A click (or ↓ and Enter)
    adds the name as a chip.
  - The ticked totals (LRs, Qty, To pay, Paid) and **Next: memo details (F4)**, which is off while nothing is ticked.
- **How filters combine:** different filters must all match (AND); several values inside one filter mean any of them
  (OR). The booked-from date filter is removed.
- **Step 2 = Memo details**, the 4.6 window extended, opened by Next:
  - **Left:** the truck boxes (Truck, Driver, To, From, Truck hire, Loading hamali), then Hamali rate and Commission %.
    The date stays automatic, with the System PIN to change it, as today.
  - **Right:** the ticked totals in a row of four, the settlement steps and the round figure.
  - Save & print (F4) / Save only / Esc back with the ticks kept.
  - **To** is filled in when exactly one station is filtered; From is Yavatmal.
  - Every rule of 4.6 stays (empty boxes refused, 0 allowed, one save per uid, the challan number issued inside the save).
- `MemoPanel` disappears from the page; its header boxes, checks and messages move into the window. A header refused
  by the keeper keeps the window open with the boxes marked.
- **Saved Memos** is its own page: today's Saved memos tab, unchanged inside. Jumps from search and the Dashboard that
  opened the Saved tab now open this page. F5 still opens Loading Memo.

**5. Memo print like DM.**
- Columns: Consignor · Consignee · LR No · Particulars · **Quantity** · To pay · Paid · **Hamali** · **Total** ·
  Wasuli, then the totals row, then Details of report.
- **"Pak" is renamed Quantity**, and "Total articles" becomes **Total quantity** in the Details block, the window and
  the saved memo card.
- Total per LR = freight + hamali (`lrAmounts`).

## Rules for this slice
- The name search is a keeper read (named route, SQL `GROUP BY … ORDER BY count DESC LIMIT 6`, only booked LRs, the
  other filters applied in SQL). One more row than shown tells the screen there are more. Rule 3: nothing large comes to
  the screen.
- **A picked name is either a master firm (by id) or a walk-in name (the exact text as booked).** The station list is
  one `GROUP BY` read.
- The fixed print lines are DM's two constants (DM `src/constants/company.ts`, "set once, never changed"):
  `COMPANY_NAME = 'Sundeep Freight Movers'` and `COMPANY_LOCATION = 'Yavatmal'`. They live in one place, and the
  keeper's print and the screen read them from there. No address, phone or GSTIN lines (DM prints none).
- No migration (schema stays v5). Old `settings` rows are left alone.
- All text in `src/strings.ts`; deleted strings are removed, not left unused. `KEEPER_VERSION` bump. Version **0.6.0**.
- Everything at 1024 × 768 with the taskbar; the right column scrolls by itself, and the Next card always stays visible.

- Next is off with nothing ticked. Esc from Memo details keeps the ticks. To is filled from a single station filter.
  A refused header keeps the window open and marks the box.

- New LRs get Yavatmal as From with no defaults setting. Old History rows for the removed settings still render.
