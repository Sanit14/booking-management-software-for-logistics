# Session 3.5 — plan (Firm Accounts)

## Primary goal
The owner opens **Firm Accounts**, finds a firm, picks a period and sees what that firm sent and received: totals, growth against
the period before, a 12-month chart, its top parties / stations / trucks, every LR with its amounts and wasuli state, and can
print or save an A4 statement. Read-only: nothing here changes an LR, memo or collection.

## Phase 0 — What exists (read before planning; use these, invent nothing)
**How this serves the goal:** the page is built only from rows and helpers that already exist, so it cannot disagree with LR Entry, Loading Memo or Wasuli.

- Schema v2 already has what is needed: `lrs_by_consignor (consignor_id, lr_date)`, `lrs_by_consignee (consignee_id, lr_date)`, `lrs_by_memo`, `wasuli.lr_id UNIQUE`. **No migration.** A cancelled memo sets its LRs back to `booked`, `memo_id NULL`, so `memo_id IS NOT NULL` = on a saved memo.
- Money: `lrAmounts` (`keeper/money.ts`) is the one definition; its SQL twin is `((topay+paid) × stax_bp + 5000) / 10000` per LR, summed (`SUMS` in `keeper/memos.ts:93`). The statement totals reuse that fragment and a dbtest compares it with `lrAmounts` (as 3.1 did). `inr(paise)` formats paper.
- Paging: keyset `(lr_date, lr_no)` (a date fixes the year), 100 a page, one row over to know there is a next page (`listSql` in `keeper/wasuli.ts`, `pendingSql` in `keeper/memos.ts`). Query text is built from fixed fragments; only values are bound.
- Plumbing for a new read group: `shared/keeper.ts` types + `KeeperApi`, route list + `if (url.startsWith(...))` block in `keeper/server.ts`, handler in `electron/keeperBridge.ts`, `electron/preload.ts`, `useKeeperData(fetcher, tables)` on the screen. `KEEPER_VERSION` 14 → **15**.
- Print: `print/template.ts` (`pageDocument`, `companyBlock`, `esc`, `A4`), `print/memo.ts` (`paginate`, `FIRST_ROWS/NEXT_ROWS/TOTALS_ROWS`), `electron/print.ts` (`initPrint`/`run`, `renderPdf`), `keeper/print.ts` (`makePrint`, `done`), `print/testing.ts` (samples, `matchSnapshot`), `electron/print.electrontest.ts` (real PDFs, `noOverrun`).
- Screen: `Table`, `TypeAhead`, `Chip`, `Card`, `Field`, `SelectField`, `Toast`, `usePrint`, `useKeeperData`; `Jump` (`src/logic/searchResults.ts`) + `App.pick` already open an LR (`{to:'lr', id}`) and a memo (`{to:'memo', id}`). `DashboardSummary.date` = the keeper PC's today (App already holds it).
- DM, for look and behaviour only: `Firms.tsx`, `FirmDetail.tsx` (`Kpi` "vs before", `GrowthChart` percentages only, `TopList`), `firms.cjs` (`previousPeriod` = the same number of days just before; the month in progress is not compared).
- Card line "Done when" 1 (HANDOFF item 13): already reads "All tests pass inside `npm run check`" — nothing to fix.
- **Anti-patterns:** no generic query route; no SQL in the screen; no money maths in the screen (it only formats); no `LIMIT`-less list; no `@media print`; no `ORDER BY id`; nothing newer than Chrome 108 / Node 16.17 (no chart library, no `color-mix`, no CSS nesting); never touch DM's port, data or backups.

## Decisions I took where the card is silent (change any before I build)
1. **Period = LR date.** Every figure (rows, KPIs, chart, tops) counts the firm's non-cancelled LRs dated in the period. "Trips" = distinct saved memos those LRs are on. "Wasuli collected" = collected amount of those LRs' wasuli rows (not by collection date). So statement totals and KPIs always agree.
2. **Both** = LRs where the firm is consignor **or** consignee; an LR with the firm on both sides counts once. Totals shown are for the role tab open (Both default).
3. **Chart:** bars = growth % of freight against the month before; the month in progress and future months have no bar (DM's rule: half a month against a whole one always looks like a fall); growth is `null` when the base is 0.
4. **Layout (1024×768, no page scroll):** list page; opening a firm replaces it with the statement: top block (name, Back, Print, Save PDF, period presets + custom dates, role tabs, 5 KPI cards) and below it two tabs — **LRs** (default: table + totals strip, scrolls in its own box) and **Growth & top lists** (12-month chart + three top lists). Stacked, the chart + lists + table do not fit 768 px.
5. **Paper:** A4 portrait, columns LR · Date · Other party · To · Qty · To pay · Paid · Charges + tax · Total; the totals strip carries LRs, Qty, To pay, Paid, Charges, Tax, Total and, when above 0, wasuli owed / collected. **At most 1,000 rows per printout** (a data: URL over 2 MB is refused by Chromium): more is refused with "choose a shorter period".
6. **Ctrl+K:** Enter on a firm still opens Masters (unchanged); **Ctrl+Enter** or the row's **Account** button opens its account.
7. Top parties group by the name as booked (a renamed firm shows under both names). Walk-ins have no firm row and never appear.
8. A statement print writes an audit row `print.firm` (seat, firm, `how`, from, to, role), like memo / LR prints; reads write nothing and publish no event.

## Phase 2 — Keeper reads
**How this serves the goal:** this is where every figure on the page comes from; SQL does the filtering, summing and grouping so the screen only draws.
- `keeper/firmAccounts.ts` (`makeFirmAccounts(now)`), five named reads:
  - `accounts(filters, cursor)` — all firms (active + inactive), name / station / phone, LRs as consignor, as consignee, last LR date; filters: text (`instr(name_key, key)`), station, "has LRs in the period", show inactive; order `name_key`, keyset, 100 a page; the page of firms is picked first, then counted through the two indexes.
  - `statement(firmId, from, to, role, cursor)` — rows (LR, date, role, other party, From → To, particular, qty, to pay, paid, charges, tax, total, Booked / Loaded + challan id and no., wasuli state and amounts) by `(lr_date, lr_no)`, 100 a page; **totals of the whole period from SQL** in the same answer.
  - `statementTop(firmId, from, to, role)` — top 5 other parties, To stations, trucks (through memos), with LR counts.
  - `kpis(firmId, from, to, role)` — period and previous period: LRs, trips, qty, freight, total, wasuli collected, growth %.
  - `months(firmId, year, role)` — 12 rows: LRs, freight, growth vs the month before.
- Routes `/firms/accounts|statement|top|kpis|months` (known-list + one block in `server.ts`, reads only, no event, nothing logged); bridge `keeper:firms-*`; preload `firms.*`. Unknown firm id → `master-missing`.
- Tests (`keeper/firmAccounts.dbtest.ts`, plus cases in `server.test.ts`):
  - list: counts per role, each filter, inactive, order, paging at 100 / 101, **EXPLAIN: no scan of `lrs`**, 3,000 firms < 100 ms;
  - statement: rows per role, cancelled left out, from / to inclusive, across 1 January, a firm on both sides counts once, totals = sum of `lrAmounts` over the rows (odd amounts, six tax rates), wasuli states, paging 100 / 101, **EXPLAIN**, 20,000 LRs for one firm < 100 ms;
  - tops, kpis (previous dates, growth, `null` on a 0 base, trips counts a memo once), months (12 rows, January vs December, current month null);
  - server: routes answer, bad bodies 400, no event for a read, no firm name or amount in `keeper.log`.
- Verify: `npm run check` green; mutation check (count a cancelled LR, or drop the "both counts once" rule → a named test fails).

## Phase 3 — Statement print
**How this serves the goal:** the owner gets the statement on paper / PDF, split into sheets with the header repeated and the totals on the last one, exactly like the memo.
- `print/memo.ts`: `paginate` takes capacities as optional arguments (memo keeps its constants); `print/statement.ts`: `statementHtml`, `statementFileName` (`Statement-<firm>-<from>-<to>.pdf`), own `FIRST/NEXT/TOTALS` constants set by the real-PDF test.
- `keeper/print.ts`: `firmStatement(db, firmId, from, to, role)` → `PrintFirmStatement` (text only, `inr`); over 1,000 rows → refusal `print-too-long`; `done` accepts `kind: 'firm'`; route `/print/firm-statement`.
- `electron/print.ts`: `print:firm-statement` through the same `run` (one `busy` flag, same Save / Print flow); preload `print.firmStatement`.
- Tests: `print/statement.test.ts` (paginate for 0…1,000, header on every sheet, totals once, escaping, black only, ≥ 9 pt, snapshot), `keeper/print.dbtest.ts` cases (= `statement` figures, too long, audit row, none for a missing firm), `print.electrontest.ts` cases (60 rows = 2 sheets, every sheet edge, 1,000 rows, 100-character names, `noOverrun`).
- Verify: `npm run check` green (the real-Electron step runs on this PC, not on GitHub).

## As built (where it differs from the plan above)
- Capacities are 36 / 43 / 4 rows (not 35): measured by `electron/print.electrontest.ts` (smallest slack 14.9 mm). The Date column was first 17 mm and printed "02-10-2…": found by reading the rendered PDF, fixed (13 / 20 / 34 / 20 / 9 / 22 / 22 / 24 / 26 mm), and the real-PDF test now fails when the LR number, date, quantity or an amount is cut.
- On screen the Freight cell shows to pay or paid with its label, and Charges shows the tax as its second line: the screen must not add money, so there is no "charges + tax" figure there (the printout has one, added by the keeper).
- The statement view's state lives in a module variable in `FirmAccountsPage.tsx` so a visit to an LR or a challan and back finds the account as left.
- Print `done` for a firm statement carries its period and role (`asPrintDone` refuses a firm print without them).
- Not done: the real Electron window and the Windows print / save dialogs (an installed keeper holds port 47715); proven instead in the browser pane against a throwaway keeper, by the PDF test and by reading the rendered pages. Owner steps are at the top of `HANDOFF.md`.
