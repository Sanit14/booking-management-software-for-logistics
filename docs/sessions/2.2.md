# Session 2.2 — LR Entry (and live updates between seats)

## Goal
A booking clerk types an LR by keyboard only and saves it with F4 in under a second; the LR gets its number
inside the save; today's list and totals update on **every** seat at once. This is the page the client uses
hundreds of times a day, so speed and keyboard flow matter more than anything else here.

`computeHamali`, `manualFields`) — behaviour only, do not copy code.

## Part 1 — Change events (do this first; the LR list depends on it)
- Keeper: `GET /events` (server-sent events, 127.0.0.1 only). After every **committed** write the keeper sends
  `{ tables: [...], ids?: [...] }` (e.g. `{tables:['lrs']}`, `{tables:['stations']}`). Nothing is sent for a
  rolled-back write.
- Main subscribes once per seat and forwards on IPC `keeper:changed`; it re-subscribes after a watchdog
  restart. Preload: `keeper.onChanged(cb)` → unsubscribe.
- Screen: one hook (e.g. `useKeeperData(fetcher, tables)`) that loads, keeps only the newest answer, and
  refetches only when an event names one of its tables. No timers, no reload on page change.
- Switch the Masters page and pick lists to it (a firm added on seat 1 appears in seat 2's lists).

## Part 2 — LR Entry
**Keeper**
- `lrs.create(input)` — one transaction: validate → number from `nextNumber('lr', lr_date)` → insert →
  optional walk-in firm insert → audit row → commit → event. Returns the saved LR with its amounts.
- `uid` comes from the screen (one per open form, `crypto.randomUUID()`); the same `uid` sent twice returns
  the first saved LR instead of a second one (safe retry).
- `lrs.preview(input)` — no write; returns `lrAmounts` (freight, charges, service tax, total) and charge
  defaults for the chosen option and quantity. The screen shows these live; **the screen never calculates money**.
- `lrs.byDate(date)` — that day's LRs newest first (by `lr_no`), `LIMIT 1000`, plus totals from SQL
  (`COUNT`, `SUM(qty)`, `SUM(topay)`, `SUM(paid)`).
- Settings used (add to Settings page, Admin PIN to change): **booking station** (default From station),
  **default charge option**, **default service tax %** (start at 0).
- Validation (keeper refuses, screen shows the message on the field):
  consignor and consignee required (firm or walk-in text); to station required and ≠ from station;
  particular required; quantity whole number ≥ 1; to pay and paid not both > 0; all money ≥ 0 and parseable;
  date = today unless changed with the System PIN; no future dates.
- `KEEPER_VERSION` bump.

**Screen (direction A, 1024×768, no page scroll)**
- Left: the form. Right: today's LRs (Table) with the totals strip, Booked/Loaded counts as chips.
- Field order and Enter flow: Consignor → Consignee → To station → Particular → Quantity → To pay → Paid →
  Charge option → Godown bhada → Godown insurance → Delivery charges → Hamali → Wasuli → Service tax %
  → Save. (From station and date are prefilled and skipped by Enter; click or Shift+Tab to reach them.)
- **LR number:** shown as "New" with the expected next number in grey; the real number comes back from the
  save and is shown in the success toast "LR 1248 saved" and at the top of the list.
- **Date:** today, read-only; a "Change date" button asks the System PIN, then allows a past date.
- **Consignor / Consignee:** TypeAhead over active firms (portal list from 2.1); the last row is
  "Walk-in — keep this name". A walk-in shows an "Add to firms" tick box (**unticked by default**); ticked →
  the firm is created in the same save (similar-name rule from 2.1 → confirm dialog before saving).
- **Charges:** picking Option 1 / Option 2 / Blank fills godown bhada, insurance, delivery charges and hamali
  from the rule (hamali per dag × quantity); a value the clerk typed by hand is kept when quantity or option
  changes (DM's `manualFields` behaviour). Charge option defaults to the last one used on this seat, else the
  Settings default.
- Live amounts box (from `lrs.preview`): Freight · Charges · Service tax · **Total**.
- **Save:** F4 or the Save button or Enter on the last field. Saving is disabled while a save is in flight.
  After save: toast, form clears (keeps date, From station, charge option, service tax %), focus to Consignor.
- F4 comes from one key-map constant; Session 2.4 makes keys user-configurable.
- PF is **not** on the form (column stays 0) unless the owner asks for it.

## Tests
- Database: number issued in the save and per year; same `uid` twice → one LR; walk-in with and without
  "Add to firms"; every validation refusal writes nothing; date change needs the System PIN; preview amounts =
  saved amounts = `lrAmounts`; `byDate` order and totals; audit row per LR.
- Events: one event per committed write, none on rollback; two keeper clients both receive it; a client that
  reconnects after a keeper restart keeps receiving events.
- Pure: Enter flow order; manual-override charge logic.
- Speed (real keeper, test): 300 LRs saved in a loop → average save under 150 ms; `byDate` with 300 rows
  under 50 ms.
