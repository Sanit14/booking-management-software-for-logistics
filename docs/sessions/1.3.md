# Session 1.3 — Schema v1, numbering and money

## Goal
The real database: every table from the Build Plan, created by ordered migrations, plus the three pieces of
logic everything later depends on: **yearly numbering inside a transaction, money in paise, and the audit
trail**. No screens. Proven entirely by tests.

## Decided rules for this slice
**Migrations**
- `keeper/migrations.ts`: an ordered list. Each migration runs in **one transaction** and bumps
  `schema_version`. Running them twice changes nothing. Migration 1 = schema v1 below.
- Bump `KEEPER_VERSION` (schema changed, so a running older keeper must be replaced).

**Schema v1** (every business table also has `created_at`, `updated_at`, `seat`, `version INTEGER NOT NULL DEFAULT 1`)
- `stations(id, name, name_key UNIQUE, active)`
- `firms(id, name, name_key UNIQUE, station_id → stations, phone, active)`
- `trucks(id, number, number_key UNIQUE, active)`
- `drivers(id, name, phone, active)`
- `counters(name, year, last, PRIMARY KEY(name, year))` with `name IN ('lr','challan')`
- `lrs(id, uid UNIQUE, lr_year, lr_no, lr_date, consignor_id → firms NULL, consignor_name, consignee_id → firms
  NULL, consignee_name, from_station_id, to_station_id, particular, qty, topay_paise, paid_paise,
  charge_option IN ('option1','option2','blank'), godown_bhada_paise, godown_insurance_paise,
  delivery_charges_paise, hamali_paise, pf_paise, wasuli_paise, stax_bp, status IN ('booked','loaded','cancelled'),
  memo_id → memos NULL)`
  - `UNIQUE(lr_year, lr_no)`; every `*_paise` and `qty` `>= 0`; `stax_bp BETWEEN 0 AND 10000`;
    `NOT (topay_paise > 0 AND paid_paise > 0)`; `(status = 'loaded') = (memo_id IS NOT NULL)`.
  - Indexes: `(lr_date)`, `(status, to_station_id, lr_date)`, `(memo_id)`, `(consignor_id, lr_date)`,
    `(consignee_id, lr_date)`.
- `memos(id, uid UNIQUE, challan_year, challan_no, memo_date, truck_id → trucks, driver_id → drivers,
  from_station_id, to_station_id, truck_hire_paise, loading_hamali_paise, frozen_lr_count, frozen_qty,
  frozen_topay_paise, frozen_paid_paise, frozen_charges_paise, frozen_stax_paise, status IN ('saved','cancelled'))`
  - `UNIQUE(challan_year, challan_no)`; indexes `(memo_date)`, `(truck_id, memo_date)`.
- `audit_log(id, at, seat, action, entity, entity_id, before_json, after_json)`, index `(entity, entity_id)`.
  Append-only: no update or delete statement for it anywhere in the code.
- `settings(key PRIMARY KEY, value)`. Seed the three charge options from DM's defaults, **converted to
  paise**: option1 = godown bhada 5, godown insurance 5, delivery charges 2, hamali 10 per dag;
  option2 = 2, 3, 3, no hamali; blank = all 0. (Rule shape: same as DM's `CartageRule`.)

**Logic (pure where possible; one file each, tests next to them)**
- `keeper/money.ts`
  - `parseRupees(text) → paise` ("1,250.50" → 125050; "" → 0; negative, letters or more than 2 decimals → error).
  - `taxPaise(basePaise, bp) = floor((basePaise × bp + 5000) / 10000)` (round half up). The **only** tax code.
  - `chargesFor(rule, qty)` → `{ godownBhada, godownInsurance, deliveryCharges, hamali }` in paise
    (hamali per dag × qty, flat, or none, as in DM).
  - `lrAmounts(lr)` → `{ freight, charges, stax, total }`: freight = to pay or paid (never both);
    charges = godown bhada + godown insurance + delivery charges + hamali + pf; stax = `taxPaise(freight,
    stax_bp)`; total = freight + charges + stax.
    *Assumption to confirm with the client in 2.2: the printed total is the same for to pay and paid LRs; the
    mode only says who pays.*
- `keeper/numbering.ts`: `nextNumber(db, 'lr' | 'challan', date)` — year is taken from the **record's own
  date** (not today), 1 January boundary; insert-if-missing then `UPDATE … RETURNING last`. Must be called
  inside the caller's transaction; throws if not.
- `keeper/names.ts`: `nameKey(text)` = lowercase, trimmed, inner spaces collapsed (used for every `*_key`).
- `keeper/audit.ts`: `writeAudit(db, { seat, action, entity, entityId, before, after })`.
- **Blank-database guard upgrade:** on clean shutdown the marker also stores the count of business rows
  (lrs + memos + masters). Opening with 0 business rows when the marker says > 0 → safe mode.

## Tests (node:test; database tests use the Electron-as-node harness from 1.2)
- Migrations from an empty file reach v1; running again is a no-op; every table, index and CHECK exists.
- Constraint tests: a row with both to pay and paid is refused; `loaded` without `memo_id` is refused;
  negative paise refused; duplicate `(lr_year, lr_no)` refused.
- `parseRupees`: "0", "", "1250", "1,250.5", "1,250.50", "12.345" (error), "-5" (error), "abc" (error).
- `taxPaise`: 0%, 5% of 1000 rupees, a half-paisa case that must round up, 100%.
- `chargesFor`: per-dag hamali × qty, flat, none, qty 0.
- `lrAmounts`: to pay LR, paid LR, charges-only LR (no freight), zero LR.
- `nextNumber`: first number of a year is 1; consecutive calls give 1, 2, 3; a 31 Dec date and a 1 Jan date
  give separate series; LR and challan series are independent; calling outside a transaction throws;
  a rolled-back transaction does **not** burn a number.
- Concurrency: two keepers can't run (1.2), so prove serial safety instead: 200 inserts in a loop give
  1..200 with no gap or duplicate.
- Audit row written by a sample insert inside the same transaction; rolled back together.
- Guard upgrade: marker with 5 business rows + database with 0 → safe mode.

## Out of scope
