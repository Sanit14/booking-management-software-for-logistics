# Session 3.3 — Printing: loading memo, LR, PDF

## Goal
The loading memo prints on A4 on the client's printer (same printer as DM) in the layout from the spec, and
can be saved as PDF and reprinted any time. Each LR can be printed too. Printing never touches the app's own
page styles (DM's blank-print bug).

Look first: DM's `src/components/MemoPrint.tsx` (A4, black on white, serif, ruled table) — layout idea only.

## Decided rules for this slice
**Print engine (one, used by every printout)**
- A hidden print window (`BrowserWindow`, `show:false`, no preload, no node, offline) loads a print page built
  from its **own** small HTML template + CSS (in `print/`). The app's CSS is never loaded there; no global
  `@media print` anywhere in the app (CLAUDE.md rule 10).
- Main gets the data from the keeper (`print.memo(id)`, `print.lr(id)` — read-only routes returning
  exactly what is printed), renders the template, then:
  - **Print** → `webContents.print({ silent: false })` (the Windows print dialog, so the clerk picks the
    printer and copies), **or**
  - **Save PDF** → `webContents.printToPDF` → a Save dialog (default name `Challan-13-2026.pdf`,
    `LR-1248-2026.pdf`).
- All amounts formatted in the keeper's answer (₹ with Indian grouping), so the template does no maths.
- Paper: A4 portrait, 10 mm margins. Text ≥ 9 pt. Black only.

**Loading memo (A4)**
- Header: firm name "Sundeep Freight Movers" (from Settings → company name, default this), heading
  **LOADING MEMO**, challan number, date, truck number, driver name, From, To, truck hire, loading hamali.
- Table (one row per LR, ordered by LR number): Sr, LR no., Consignor, Consignee, Destination (LR's To),
  Particular, Qty, To pay, Paid. Totals row: LRs, Qty, To pay, Paid — **the frozen totals** (what the memo was
  saved with). If the memo differs (3.2), print still uses frozen totals and adds a small line
  "LRs changed after saving — recalculate to update totals".
- Many LRs: the table continues on the next page with the header row repeated; "Page n of m" in the footer;
  totals only on the last page. A cancelled memo prints with a large "CANCELLED" mark.
- Buttons in the memo view (3.2): **Print**, **Save PDF**. Also "Print" in the toast after Create memo.

**LR (bilti)**
- Default layout until the owner sends a photo of their bilti: **A5 landscape** (half an A4) with company name,
  "LORRY RECEIPT", LR no., date, From, To, Consignor, Consignee, Particular, Qty, payment mode (To pay / Paid),
  Freight, each charge line, Service tax %, Service tax, **Total**, and a signature line. Walk-in names printed
  as typed.
- Service tax printed (decided 22 Oct). Total = freight + charges + service tax for both To pay and Paid
  (assumption from 1.3; the owner confirms with the client).
- Buttons: **Print LR** and **Save PDF** in LR view mode (2.3), and in the LR-saved toast / Quick LR.
- A cancelled LR prints with "CANCELLED".

**Settings** — "Company on printouts" card (Admin PIN): company name, address line, phone line, GSTIN line
(optional). Used by both printouts.

Every print and PDF writes one audit row (`print.memo` / `print.lr`, seat, id) — no reprint limit.
`KEEPER_VERSION` bump. No migration.

## Tests
- Pure: memo page-splitting (rows per page, header repeat, totals only on the last page), Indian money
  formatting, the template's HTML escapes names (`<`, `&`, quotes).
- Database: `print.memo` answer = frozen totals and LRs in LR-number order; cancelled / differs flags;
  `print.lr` amounts = `lrAmounts`; audit row per print.
- Real: `printToPDF` of a 1-LR memo, a 60-LR memo (≥ 2 pages) and an LR produces PDFs (size > 0, page count
  checked by counting `/Type /Page`). Snapshot the rendered HTML of each template.

## Out of scope
Batch printing several memos, printing reports (4.1), printer setup inside the app, thermal/dot-matrix layouts.

## Done when
1. All tests pass inside `npm run check`.
2. Real window: a saved memo → Print → the Windows print dialog → prints on A4; Save PDF opens correctly.
3. A 60-LR memo prints on 2+ pages with the header row repeated and totals on the last page.
4. An LR prints on A5 landscape with all amounts; a cancelled one shows CANCELLED.
5. The app's own pages look the same after printing (no leaked print styles).
6. Owner: print one memo and one LR on the **client's printer** (or the same model) and compare with the
   paper they use today — note anything to move.
7. `HANDOFF.md` updated; changed files listed with one suggested commit message and the worktree steps
   (commit and confirm before removing — never `--force`).
