# Session 1.6 — Installer and first install on a real seat

## Goal
A real Windows installer (`Booking Manager-Setup-<version>.exe`) that installs once on the NComputing host and
runs on every seat, side by side with DeliveryManager, and keeps working when the seat that started the keeper
logs off. This is the first test on the client's actual hardware.

(Auto-update, GitHub Actions and the signing key move to Session **1.7**, together with the System/Admin PIN that
the update button needs. This session needs no GitHub repo.)

## Look at DM first (pattern only, do not copy)
`C:\Users\HP\Desktop\dm - auto update\dr-testing\`: `package.json` → `build` section, `build/installer.nsh`
(folder creation + permissions), `electron/process-scan.cjs`.

## Decided rules for this slice
**Packaging**
- electron-builder, exact version DM uses (from DM's `package-lock.json`), `electronVersion` 22.3.27, NSIS,
  same CPU architecture DM ships. `perMachine: true` (one install for all Windows users = all seats),
  `oneClick: false`, desktop + Start-menu shortcut "Booking Manager", app id `com.sundeepfreight.bookingmanager`.
- `npm run dist` → `release/Booking Manager-Setup-<version>.exe`. Version from `package.json` (0.1.0 now).
- `better-sqlite3` is `asarUnpack`ed; the keeper is started from the packaged app the same way as in dev.
  `*.test.js`, `*.dbtest.js`, `scripts/`, `docs/`, sources and maps are left out of the package.
- App icon made from the sidebar logo (teal badge, orange truck) as a 256×256 PNG at `build/icon.png`;
  no new image library (render it with Electron or write it by hand).
- Production CSP: remove `ws://127.0.0.1:5173` and anything else dev-only. Dev keeps working.

**Installer folders and permissions** (`build/installer.nsh`)
- Create `C:\BookingManagerData`, `C:\ProgramData\BookingManager` (with `logs\`), and `D:\BookingManagerBackups`
  if a D: drive exists; give the local **Users** group modify rights on each (`icacls`), because seats are
  non-admin Windows users and DM hit EPERM exactly here.
- **Uninstall never deletes** the data folder, the backups, or ProgramData. Reinstall finds the same data.
- Never touch any DeliveryManager folder, shortcut, registry key or port.

**Keeper survival (decided: seat-side watchdog, no Windows service)**
- Every open app checks the keeper with `/health` every **15 s** (a liveness ping, not a data poll) and on any
  failed request. If the keeper is gone, the app starts a new one (same single-instance rule) and the status
  box shows "Reconnecting…" until it is back. No data is lost because every save is already committed.
- The ping interval is one named constant. Nothing else polls.

**Window**
- Open **maximised** by default; minimum size stays 1024×768. Kiosk/full-screen is not used (clerks switch to
  DM and other programs). The hardware check below confirms the page area at the seats' real resolution.

**Visible version**
- Settings page shows app version, keeper version, schema version, data folder and backup folder.

## Tests
- Pure: watchdog decision logic (healthy / missing / wrong app / version older → what to do), with fake probes.
- Existing suite stays green. `npm run dist` must succeed on the dev PC.

## Out of scope
Auto-update, GitHub Actions, code signing, PINs (1.7). Any business page.

## Done when (on the dev PC — Claude Code proves these)
1. `npm run dist` builds the installer; the package contains no test files, no sources, no source maps.
2. Install on the dev PC → the Start-menu shortcut opens the app maximised, keeper connected, backup made.
3. Kill the keeper process in Task Manager while the app is open → within ~15 s the status box shows
   "Reconnecting…" and then connected again.
4. Uninstall → `C:\BookingManagerData` and the backups are still there; reinstall → same data, no safe mode.
5. Installing and running Booking Manager does not disturb DM on the same PC (DM opens, its keeper still on 47615).
6. `HANDOFF.md` updated, changed files listed with one suggested commit message and the worktree merge steps.

## Hardware check (owner, on the client's NComputing host via AnyDesk — results go back to Claude in chat)
1. Install as administrator on the host. Note the Windows version and whether it is 32- or 64-bit.
2. Open the app on **two seats** (two Windows users) at the same time: both say connected, each shows its own
   seat name, Task Manager on the host shows **one** keeper.
3. Log off the seat that opened the app first: the other seat shows "Reconnecting…" and comes back within ~30 s.
4. A backup file appears in `D:\BookingManagerBackups` (or the reason it can't, shown in the status box).
5. At the seat's real screen resolution: nothing clipped, fonts look right, text is readable from the clerk's chair.
6. DeliveryManager still opens and works on the same seats at the same time.
7. Note how long the app takes from double-click to usable.
