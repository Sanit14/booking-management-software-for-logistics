# Session 3.2 — Saved memos: view, edit, move LRs, cancel, recalculate

## Goal
A saved memo can be found, opened and corrected: header fixed, an LR taken off or moved to another memo, LRs
added, the whole memo cancelled. Memo totals stay **frozen** (what was printed), but the app shows clearly when
a memo no longer matches its LRs and lets an authorised person **Recalculate**. Every change is audited and
seen by every seat at once.

## Decided rules for this slice
**Saved memos page section**
- Loading Memo page gets a second tab: **Saved memos** (the 3.1 screen becomes the **New memo** tab).
- Saved memos list: date range (default today), truck, To station filters; columns challan, date, truck,
  driver, To, LRs, Qty, status chip (Saved / Cancelled), and a **Differs** chip when needed. Newest first by
  (date, challan no). Keyset paging, 100 per page. Ctrl+K picks (3.1) open the memo here.
- Opening a memo shows the 3.1 read-only view with action buttons: **Edit header**, **Remove LR**,
  **Move LR**, **Add LRs**, **Recalculate**, **Cancel memo**, **History**.

**Edit header (System PIN)**
- Date (same year only — the challan number belongs to that year's series), truck, driver, From, To, truck
  hire, loading hamali. Same validation as create. `version` check: stale → refused with the current memo.
- Challan number never changes. Audit with before/after of changed fields only.

**Take LRs off / move / add (System PIN)**
- **Remove LR:** pick LRs on the memo → they go back to `booked`, `memo_id` NULL, `version + 1` (they reappear
  in pending on every seat). A memo can't be left with 0 LRs: removing the last one is refused ("Cancel the memo
  instead").
- **Move LR:** pick LRs → choose a target memo (same flow, a Saved memo, not cancelled) → one transaction
  updates `memo_id`. Both memos are marked as differing (below).
- **Add LRs:** opens the pending list (3.1 filters) in a dialog → tick → added in one transaction with the
  **same claim guard** as create (an LR loaded by another seat meanwhile → whole change refused, names it).
- Each is one `IMMEDIATE` transaction with the audit rows for the memo(s) and each LR, then one event
  `['memos','lrs']`.
- LR Entry (2.3): the "LR is on memo n — remove it from the memo first" message gains a button that opens that
  memo on the Saved memos tab.

**Frozen totals and the "Differs" flag**
- Frozen totals on the memo never change by themselves.
- A memo **differs** when its current LRs' count, quantity, to pay, paid, charges or service tax (computed in
  SQL the same way as at save) no longer equal its frozen totals — after an LR edit (2.3), remove, move or add.
  Computed when read (no stored flag), shown as a **Differs** chip in the list and, in the view, a side-by-side
  "Saved totals" vs "Totals now".
- **Recalculate** (Admin PIN — it changes what was printed): copies the current totals into the frozen columns,
  audit row with old → new. The chip disappears.

**Cancel memo (Admin PIN + reason)**
- All its LRs go back to `booked` (they reappear in pending), memo status `cancelled`, reason in the audit row.
  The challan number is never reused. Cancelled memos stay listed, greyed, excluded from Dashboard counts
  (memos today, trucks out).
- No "restore memo": re-create it from the pending LRs if needed (simpler and keeps numbers honest).

**History** — like LR history (2.3): who, when, what, for the memo; newest first, at most 50.

`KEEPER_VERSION` bump. **No migration** expected; if one is needed, add version 2.

## Tests
- Database: header edit (changed-only audit, stale refused, year rule, PIN); remove (back to booked, last LR
  refused); move (both memos, target must be saved, same-memo refused); add with the claim guard (taken LR →
  whole change refused and named); differs computed correctly after each kind of change incl. an LR edit from
  2.3; recalculate needs Admin PIN, clears the difference, audit old → new; cancel needs Admin PIN + reason, all
  LRs booked again, number not reused, Dashboard counts exclude it; history; one event per committed change,
  none on refusal; `EXPLAIN QUERY PLAN` for the list and the differs query.
- Real keeper: one seat removes an LR while another adds it to a different memo → never on two memos.

## Out of scope
Printing and reprinting (3.3), Wasuli (3.4), Firm Accounts (3.5), keeping New-memo ticks when leaving the page
(decide after the owner's real test).

## Done when
1. All tests pass inside `npm run check`.
2. Real window: open a memo from Saved memos → remove one LR (System PIN) → it's back in pending on another
   seat → the memo shows **Differs** with saved vs now → Recalculate (Admin PIN) → chip gone.
3. Move an LR between two memos; add a pending LR to a memo; edit an LR on a memo in LR Entry → its memo shows
   Differs.
4. Cancel a memo with a reason → its LRs are pending again, the memo is greyed, Dashboard counts drop.
5. `HANDOFF.md` updated; changed files listed with one suggested commit message and the worktree steps
   (commit and confirm before removing — never `--force`).
