# Session 4.1 — plan (Reports)

## Primary goal
The owner opens **Reports**, picks one of seven reports and a period, sees the rows and the totals, clicks a row to reach the LR, memo
or firm account behind it, and prints or saves an A4 PDF of exactly what is on screen. Read-only: no report changes an LR, memo or
collection, and **the same period gives the same totals in every LR-based report**.

## Phase 0 — What exists (read before building; use these, invent nothing)
**How this serves the goal:** every figure comes from rows and SQL that already exist, so a report cannot disagree with LR Entry, Loading Memo, Wasuli or Firm Accounts.

- Schema v2 has the indexes needed: `lrs_by_date (lr_date)`, `lrs_pending (status, to_station_id, lr_date)`, `lrs_by_consignor|consignee (id, lr_date)`, `lrs_by_memo`, `memos_by_date`, `memos_by_truck`, `wasuli_by_status`, `wasuli_by_collected`. **No migration.** `KEEPER_VERSION` 15 → **16** (`shared/keeper.ts:6`).
- Money: `lrAmounts` (`keeper/money.ts`) is the definition; its SQL twin (charges, `(freight × stax_bp + 5000) / 10000` per LR, total) now lives in **two** files: `keeper/firmAccounts.ts:38-46` (`l.`-prefixed) and `keeper/memos.ts:93-96` (`SUMS`, un-prefixed). A third copy is what the card says to prevent → **move it to one module first** (`keeper/lrSql.ts`, prefix as an argument), both files use it, their existing dbtests (which compare with `lrAmounts`) must stay green and unchanged.
- "Differs" for a memo is computed on read (`savedSql` in `keeper/memos.ts:109`, `differs()` at 102, "keep the two together"): Truck-wise reuses that expression (exported as a function), not a fourth copy.
- Paging: keyset, 100 a page + 1 row over (`listSql` `keeper/wasuli.ts:87`, `firmSql.rows` `keeper/firmAccounts.ts:63`); query text from fixed fragments, only values bound; EXPLAIN-test helpers (`plan`, `noScan`) in `keeper/firmAccounts.dbtest.ts:358`; speed with `fastest(n, fn)` from `keeper/testing.ts`; test world pattern `world()` in `firmAccounts.dbtest.ts:39` built from `keeper/memoTesting.ts` (`setUp`, `book`, `create`).
- Plumbing for a read group: `shared/keeper.ts` types + `KeeperApi`, route list and a `url.startsWith('/…/')` block in `keeper/server.ts` (known-list line 316, firms block 587), handler in `electron/keeperBridge.ts:305`, `electron/preload.ts:98`, `useKeeperData(fetcher, tables)` on the screen.
- Print: `print/template.ts` (`pageDocument`, `companyBlock`, `esc`, `A4`), `print/memo.ts` `paginate`, `print/statement.ts` (the model: header row, totals strip, `extraCss`), `keeper/print.ts` (`makePrint`, `done`, `MAX_STATEMENT_PRINT_ROWS` = 1000, `print-too-long`), `electron/print.ts` `run`, `print/testing.ts` samples, `electron/print.electrontest.ts` (`pdfOf`, `noOverrun`, `cutCells`).
- Screen: `Table`, `Card`, `Field`, `SelectField`, `TypeAhead`, `Chip`, `Button`, `usePrint`, `useKeeperData`, `src/logic/firmPeriod.ts` (`periodOf`, `isRange`, presets Today / This month / Last month / This year), `Jump` + `App.pick` (opens `{to:'lr'}`, `{to:'memo'}`, `{to:'account'}`); the `reports` page id, nav entry and string already exist (it shows the empty `Page`). `FirmAccountsPage.tsx` is the model for "list, drill in, Back, keep the view in a module variable".
- Spec: "Every report has a date range, totals row, print and PDF"; the Wasuli page "feeds the consignor-wise report" (so the Wasuli column = the LR's own wasuli amount).
- **Anti-patterns:** no generic query route; no SQL or money maths in the screen; no `LIMIT`-less list; no `ORDER BY id`; no `@media print`; nothing newer than Chrome 108 / Node 16.17; no new table or migration; never touch DM's port, data or backups.

## Decisions I took where the card is silent (change any before I build)
1. **Wasuli column** (Station / Consignor / Consignee-wise) = the sum of `lrs.wasuli_paise` of the period's non-cancelled LRs, no join; a dbtest ties it to the `wasuli` table's amounts.
2. **Party grouping:** a firm by its id (shown with the master name); a walk-in by the name as booked, exact text (as the 3.5 top lists). The Station column is the firm's master station, blank for a walk-in.
3. **Firm-wise** = firms with at least one non-cancelled LR dated in the period, by name. *LRs as consignor* / *as consignee* count each side; **Qty / To pay / Paid = the firm's LRs on either side, each once** — identical to that firm's Firm Accounts "Both" totals, which is where the row opens. These three are **not summed in the totals strip** (an LR between two firms would be counted twice); the strip shows the firms listed, Σ LRs as consignor, Σ LRs as consignee, and the LRs whose consignor / consignee is a walk-in, so *firms + walk-ins = the LR total of the other reports* is visible and tested.
4. **Wasuli report:** one row per agent with something in it (zero rows hidden). *Assigned* = assigned now (not by period); *Collected* = collected date in the period, the amount collected. The **Unassigned pool is not per agent**, so it is a line of the totals strip (count, amount), not a column. Wasuli rows have no drill-down (the card names none).
5. **Truck-wise:** one row per **saved** memo dated in the period (cancelled memos left out), by (memo date, challan no.); LRs / To pay / Paid are the memo's **frozen** figures, plus truck hire and loading hamali; a **Differs** chip when its LRs no longer add up (3.2's rule). Totals = sums of the frozen figures.
6. **Filters** (where they make sense): Date-wise — To station, party text (either side); Station-wise — party text; Consignor- / Consignee-wise — To station, that party's name text; Truck-wise — truck, To station; Firm-wise — firm name text; Wasuli — agent. Text = any part of the name, ASCII case ignored (as the 3.1 pending filters).
7. **Order:** Date-wise by date, Truck-wise by (memo date, challan no.), the rest alphabetical (station, party, firm, agent name); keyset on that key, 100 a page. Easy to change to "biggest first" if the owner prefers.
8. **Drill-downs:** Date → LR Entry showing that day (`Jump` gains `{to:'day', date}`; LR Entry sets its list's day box); Station / Consignor / Consignee → an in-page list of its LRs (`reports.lrs`: LR no., date, other party, To, Qty, amounts, totals, Load more, Back / Esc), an LR in it opens in LR Entry; Truck-wise → the memo; Firm-wise → Firm Accounts for that firm with the period (`{to:'account'}` gains an optional range, opened as Custom).
9. **Paper:** one generic A4 portrait template for all seven (every report has 9 columns or fewer, so no landscape), header row and "Page n of m" on every sheet, totals on the last, at most 1,000 rows per printout (more → `print-too-long`, "choose a shorter period"), capacities proven by the real-PDF test. Truck-wise marks a differing memo with `*` and a footnote. A print that went through writes the audit row `print.report` (seat, report, how, from, to, filters).
10. **Layout (1024×768, no page scroll):** left a narrow list of the seven reports (↑/↓, Enter opens it), right the period pills + filter row, the table in its own scroll box, the totals strip, Print and Save PDF. Money is shown here (the no-money rule is the Dashboard's only).

## Phase 1 — One home for the money SQL (refactor, no behaviour change)

## Phase 2 — Types and pure rules (test first)
**How this serves the goal:** a request that is not a real period, filter or cursor is refused before any SQL runs.
- `shared/keeper.ts`: `ReportKind`, `ReportQuery` (period + the filters above), `ReportCursor` (`{key, no}`), one row and one totals type per report, `ReportPage<Row, Totals>`, `ReportLr*` for the drill list, `KeeperApi.reports.*`, `PrintReport`, `PrintApi.report`, `KEEPER_VERSION = 16`.
- `keeper/reportRules.ts` (pure): `asReportQuery(kind, body)` (dates via `asRange`, ids ≥ 1, text ≤ 100, filters not meant for that report dropped), `asReportCursor`, `asLrsQuery`. Test `reportRules.test.ts`: good and bad input for every report, a stray filter is ignored.

## Phase 3 — Keeper reports (reads only, no event, nothing logged)
**How this serves the goal:** this is where every figure is added up; SQL groups, sums and pages so the screen only draws.
- `keeper/reports.ts` `makeReports(now)`: `dateWise`, `stationWise`, `partyWise(role)`, `truckWise`, `firmWise`, `wasuli`, `lrs(kind, key, query, cursor)`. Each answers `{rows (≤100), next, totals of the whole filter}` with the totals in the same answer. Group first, then page the groups by their key; Firm-wise picks its page of firms first and reads each firm through `lrs_by_consignor|consignee`.
- Routes `/reports/date-wise|station-wise|party-wise|truck-wise|firm-wise|wasuli|lrs`, bridge `keeper:reports-*`, preload and `window.bm.keeper.reports.*`; `KEEPER_VERSION` 16.
- Tests `keeper/reports.dbtest.ts` — one seeded world, worked out by hand like 3.5's (booked, loaded, cancelled; walk-ins; two years; memos with one differing and one cancelled; wasuli unassigned / assigned / collected):
  - each report's rows and totals against hand numbers;
  - **cross-report agreement** for the same period: Date-wise = Station-wise = Consignor-wise = Consignee-wise grand totals (LRs, Qty, To pay, Paid); Σ Firm-wise LRs as consignor + walk-in consignor LRs = the same LRs (and the consignee side); each Firm-wise row = Firm Accounts' "Both" totals for that firm; Σ wasuli column = Σ `wasuli.amount_paise` of those LRs; unfiltered, and with a To-station filter;
  - period edges (inclusive, across 1 January), every filter, paging at 100 / 101 / 250 for each report (none twice, none lost, in key order), cancelled LRs and memos left out, Truck-wise frozen vs current + Differs, Wasuli by collected date, an agent with only a pool/assigned row;
  - **EXPLAIN: no scan of `lrs`, `memos` or `wasuli`** for every statement (with and without a cursor); **speed: 20,000 LRs, every report's first page < 100 ms**.
  - `server.test.ts`: routes answer, bad bodies 400, a read publishes no event, no name or amount in `keeper.log`.
- Verify: `npm run check`; mutation checks (count a cancelled LR in one report; Truck-wise from current instead of frozen; drop the page cursor) → a named test fails.

## Phase 4 — Print and Save PDF
**How this serves the goal:** the owner takes the report on paper or as a PDF, split into sheets with the header repeated and the totals on the last.
- `keeper/print.ts` `report(db, query)`: the whole report (not a page), text only through `inr`, refused above 1,000 rows (`detail` = how many); `done` accepts the report kind; route `/print/report`.
- `print/report.ts`: `reportHtml`, `reportFileName` (`Report-<name>-<from>-to-<to>.pdf`), modelled on `print/statement.ts`; `electron/print.ts` `print:report`; preload `print.report`; `usePrint.report`.
- Tests: `print/report.test.ts` (paginate 0…1,000, header on every sheet, totals once, escaping, black only, ≥ 9 pt, 1,000 rows under the 2 MB data: URL, snapshots), `print.dbtest.ts` cases (= the screen's rows and totals, too long, audit row, none on cancel), `print.electrontest.ts` (a 60-row report = 2 sheets, the sheet edges, 100-character names, `noOverrun`, no cut cell).
- Verify: `npm run check`; a real 60-row PDF rendered to images and read.

## As built (where it differs from the plan above)
- **Decision 2 changed:** a walk-in is one row by its name ignoring ASCII case (not exact text), so the keyset cursor stays unique.
- **Decision 10 changed:** the seven reports are a row of tabs above the table, not a left-hand list; the money columns need about 150 px each (see `docs/decisions.md`, 2026-11-06).
- **Totals shortcut** (a report that fits one page sums its rows instead of a second pass over the LRs) was added to keep Date-wise inside the 100 ms budget; a test compares it with the totals statement.
- **Wasuli headings say "now"** (Assigned now, Unassigned pool now): they are not period-bound, a reviewer's point.
- `report-too-long` carries no row count (the read stops at the first page over the limit); the plan said "detail = how many".
- Not done in the real window: **Load more** on a report with more than 100 groups (the dbtests page every report at 100 / 101 / 250 and the drill-down list too), the arrow keys in the row of tabs, and the **Print** button's Windows dialog (Save PDF was driven).
