# Session 4.5 — The LR as the customer approved it (charges and service tax out)

## Goal
The customer has seen the app and approved the LR entry page with fewer boxes. Cut the LR down to exactly the approved
inputs everywhere it appears (LR Entry, Quick LR, the keeper, the LR print, Reports, Firm Accounts, History, Settings).
The memo's new settlement (hamali less, commission, wasuli, net, round figure) is **4.6**, not this session.

## Decided (customer, 2026-11-12)
**The LR's inputs are only these:** consignor, consignee, LR number (auto), from station, to station, particular,
quantity, to pay, paid, hamali, wasuli. The date stays automatic as today (System PIN to change). Sr no stays the row
number of a table, not a field. To pay **or** paid, never both (unchanged).
- **Removed:** the charge option (Option 1 / Option 2 / Blank), godown bhada, godown insurance, delivery charges, PF,
  service tax %, and with them the charge rates and the option and service-tax defaults in Settings (`LrDefaultsCard`
  keeps the booking station only), `src/logic/chargeFill.ts`, `ChargeDefaults`, the `defaults` part of `LrPreview`.
- **Hamali is typed on every LR** like the other amounts (no auto-fill from quantity). Wasuli unchanged.
- **The LR's money:** freight (to pay or paid) + hamali = the LR total. No tax. `lrAmounts` and its SQL twin
  `keeper/lrSql.ts` become freight, hamali, total; every place that showed "Charges" or "Charges + tax" shows **Hamali**,
  and every service-tax column, line and total goes.

## Rules for this slice
- **No migration.** The removed columns stay in `lrs` (never edit v1–v4); new LRs write them as 0 / `'blank'`; nothing
  reads them any more. The shared LR input type loses the removed fields, so the keeper cannot be sent them.
  `memos.frozen_charges_paise` now freezes the hamali sum and `frozen_stax_paise` stays 0 (4.6 reworks memo totals).
- O3 (`sameAsSaved`) compares only the fields that remain.
- **History:** old audit rows that name a removed field (charge option, godown, delivery, stax) still read as a sentence
  with old → new; new rows never carry them. Reports and Firm Accounts on old rows: only freight and hamali count.
- **LR print (A5 landscape):** parties and goods left; To pay or Paid, Hamali, Total, and Wasuli as today on the right.
  The layout is otherwise unchanged until the bilti photo arrives.
- **Reports:** Date-wise = Date, LRs, Qty, To pay, Paid, Hamali, Total. The other reports lose any charges / tax column
  they have; nothing else changes. The cross-report agreement test stays and must still hold.
- **Firm Accounts:** statement column "Charges + tax" → "Hamali"; KPIs and the growth chart unchanged otherwise.
- **The LR Entry form at 1024 × 768** gets shorter: the Enter order is consignor, consignee, from, to, particular, qty,
  to pay, paid, hamali, wasuli, save. Nothing new is added to fill the space.
- `scripts/seed-load.cjs` and `scripts/bench.cjs` stop generating charges and tax (bench must still all PASS).
- All text in `src/strings.ts`; unused strings deleted. `KEEPER_VERSION` bump. Version **0.4.0**.

## Tests
- `lrAmounts` and `lrMoneySql` agree over odd amounts: total = freight + hamali; an old row with godown / stax set adds
  only freight + hamali.
- A saved and an edited LR have the removed columns 0 / `'blank'`.
- Reports: every column set, cross-report agreement, Date-wise totals by hand; Firm Accounts statement total = Σ (freight + hamali).
- Print: LR print snapshot without charge or tax lines; statement and report prints without tax columns.
- History sentence for an old row with `staxPercent` and `godownBhada` still renders.

## Out of scope
The memo settlement window, memo print columns and the Truck-wise report (4.6); the pilot (4.7); the bilti layout.

## Done when
1. `npm run check` alone, exit 0, three times in a row.
2. Real window (`npm run dev`, throwaway data): type 10 LRs by keyboard only with the new Enter order; edit one; print one;
   Reports Date-wise and a Firm Accounts statement show Hamali and no tax anywhere; Settings has no charge options.
3. `grep` finds no `stax`, `godown`, `deliveryCharges`, `chargeOption` outside `migrations.ts`, old History wording
   and tests of old rows.
4. Bench still all PASS on the 3-year file.
5. `HANDOFF.md` updated; one line per decision in `docs/decisions.md`; changed files listed with one suggested commit
   message, the worktree steps (commit and confirm before removing — never `--force`), then `git push`,
   `gh run list --limit 3`, and the release steps for 0.4.0 from the main folder.
