# Session 2.1 — plan (Masters: stations, firms, trucks, drivers)

Status: **waiting for the owner's approval. No code written yet.**

## Primary goal
A booking clerk can type the whole client's master data — stations, firms, trucks, drivers — from the keyboard alone,
mistakes like "Shree Ganesh Traders " twice are caught, changes need the System PIN, and everything is still there
after a restart. It is also the first keeper endpoint that writes business rows, so it sets the pattern every later
endpoint copies.

## Phase 0 — Documentation discovery (done by reading the code; there is no outside API in this slice)
**How this serves the primary goal:** the new endpoints must copy the patterns that already work, not invent new ones.

Allowed building blocks (all read this session):
- `keeper/names.ts` `nameKey` (NFC, trim, collapse spaces, lower-case) — used for station/firm `name_key UNIQUE`.
- `keeper/audit.ts` `writeAudit(db, {seat, action, entity, entityId, before, after})` — throws outside a transaction.
- `keeper/pins.ts` `makePins().verify(db, 'system', pin)` → `KeeperResult<true>`; handles lockout and counting.
- `keeper/server.ts`: `known` route list, JSON-POST gate, `ok()/refuse()/sendResult()`, `seat` from `X-BM-Seat`,
  `state !== 'ready' || !db || stopping` → `no-database`. Pattern to copy: the `/pins/*` block (server.ts ~352–375).
- `shared/keeper.ts`: `KeeperResult`, `ResultCode`, `KeeperApi`, `KEEPER_VERSION` (6 → 7).
- Bridge pattern: `electron/keeperBridge.ts` `call()` + one `ipcMain.handle` per named route; `electron/preload.ts`
  one function per route; `src/global.d.ts` already types `window.bm.keeper` from `KeeperApi`.
- Schema v1 (`keeper/migrations.ts`): `stations(name,name_key UNIQUE,active)`, `firms(name,name_key UNIQUE,station_id NULL,phone,active)`,
  `trucks(number,number_key UNIQUE,active)`, `drivers(name,phone,active)`; all have `version`, `seat`, `updated_at`. **No schema change needed.**
- Screen: `Table`, `Card/PageHeader`, `Button`, `Field`, `TypeAhead`, `Dialog`, `PinDialog`, `useEnterToNext`, `useToast`, `Chip`,
  `Page` (accepts children). `PinsCard.tsx` is the pattern for a PIN-gated call (wrong PIN shakes, other refusals toast).
- Test patterns: `pins.dbtest.ts` + `testing.ts` (`freshDb`), `server.test.ts` (`startKeeper`, `callJson`, `markerPath`).

Anti-patterns to avoid: a generic query/forwarder route; deleting masters; ordering by `id`; summing/ruling in the screen;
hard-coded UI text; hard-coded shortcut keys; editing migration v1; any Node API > 16.17 or CSS > Chrome 108.

## Phase 2 — Keeper `masters.ts` + database tests (test first)
**How this serves the primary goal:** the database layer is where "no duplicates, no stale overwrite, PIN-gated, audited" is true.
- `keeper/masters.ts`: `makeMasters(pins)` → `all(db)`, `create(db, seat, kind, fields, confirmSimilar)`,
  `update(db, seat, kind, id, version, fields, systemPin, confirmSimilar)`, `setActive(db, seat, kind, id, version, active, systemPin)`.
  Explicit SQL per kind (literal strings, no string-built table names from input). Each write = one transaction with its audit row
  (`masters.create|update|activate|deactivate`, entity = table, before/after JSON, never the PIN) and returns the saved row.
  `all()` orders by `name_key` / `number_key` (drivers: `name COLLATE NOCASE, phone`), includes inactive.
  Update/deactivate call `pins.verify(db,'system',pin)` first; wrong/locked → refused, nothing written. Reactivate needs no PIN.
  Stale `version` → `master-stale` + current row. Exact duplicate (stations, firms: `name_key`, active or not; trucks: `number_key`;
  drivers: same name **and** phone) → `master-exists` + the existing row (so the screen can offer "Reactivate"). Firm / driver-name
  similar → `master-similar` + names, saved only with `confirmSimilar`. Edits re-run the same checks excluding the row itself.
- `keeper/masters.dbtest.ts` — per kind: create; duplicate refused (case/space/punctuation variants incl. `shree ganesh traders ` and
  `MH 29 BE 1234` vs `mh-29-be-1234`); similar → needs confirm → saves; stale refused; deactivate hides from the active list but the
  row stays; reactivate; audit row per write; wrong System PIN refused and nothing written; firm station must exist; ordering.
Verify: `npm run check` (db tests run under Electron-as-node).

## Phase 5 — Masters page
**How this serves the primary goal:** this is the clerk's screen.
- `src/masters/MastersPage.tsx` (+ css): four tabs with active counts (arrow keys switch); left card = search (in memory on `matchKey`),
  "Show inactive" toggle, Table (inactive rows greyed + Inactive chip); right card = form. Loads `masters.all()` on open and after its own writes.

- `src/masters/MasterForm.tsx`: fields per kind (firm: name, station TypeAhead (active stations only, no walk-in row), phone); `useEnterToNext`;
  Enter on the last field saves → toast "Firm saved: …", form clears, focus back to the first field. Typed station text with no pick = field error.
  Exists → error under the name + "Reactivate it" when the match is inactive. Similar → confirm `Dialog` listing names ("Add anyway" / "Go back").
  Row Enter/click → edit mode → Save opens `PinDialog` (System PIN, one request carries the PIN; kept in memory only for an "Add anyway" resend).
  Deactivate (PIN) / Reactivate (no PIN) on the selected row. Stale → warning toast, form re-seeded with the returned current row.
- `src/App.tsx`: `page === 'masters'` renders it. All text in `src/strings.ts` (`strings.masters`).

## Decisions I am making where the card is silent (tell me if any is wrong)
1. **Four routes with a `kind` field** (`/masters/all|create|update|set-active`), kind whitelisted, explicit SQL per kind inside the keeper — not 13 routes. Not a generic query endpoint.
2. **Every edit asks the System PIN** (phone- or station-only edits too), as the screen section says; **reactivate does not**.
3. **Drivers have no `name_key` column**, so driver duplicate / similar checks compare in the keeper over the (small) driver list inside the transaction; no migration v2. Ceiling: thousands of drivers is fine.
4. **Phone** = digits only (spaces, dashes, dots, brackets, leading `+` stripped), up to 15 digits, optional.
5. **Names** are stored trimmed with inner spaces collapsed, otherwise as typed; trucks as typed but upper-cased.
6. **Tab counts** show active rows only.
7. Similar-name check also applies when **editing** a firm / driver name.
8. Fresh worktree has no `node_modules`: first step of the build is `npm install` then `npm run postinstall` (~12 min), as in 1.5–1.7.
