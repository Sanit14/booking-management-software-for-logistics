# Session 4.2 — History page and the Admin settings left over

## Goal
1. A **History** page: everything that changed in the books — who, when, on which seat, what changed (old → new)
   — searchable, so the owner can always answer "who did this?". Every PIN-gated action must appear in it.
2. The Admin settings that earlier sessions postponed: **restore from a backup outside safe mode**, **change the
   backup folder**, **rename this seat**, and hide the developer Components card from the client.

Look first (behaviour only): DM `src/pages/History.tsx` (DM's audit-log page; DM had a name collision bug there —
show names, not ids, and never mix two entities with the same id); this app's LR History (2.3) and memo History (3.2)
panels, `keeper/audit.ts`, `keeper/backup.ts` + the 1.4 restore routes.

## Decided rules for this slice
**History (reads only from `audit_log`; no migration; `KEEPER_VERSION` bump)**
- `history.list(filters, cursor)` — newest first by (`at`, `id`); keyset 100 a page. Filters: date range (default
  last 7 days), seat, kind of record (LR, memo, wasuli, firm, station, truck, driver, agent, PINs / settings,
  backup / restore, print), action (created, edited, cancelled, restored, collected…), and "LR no." / "Challan no."
  (exact, current year unless a year is given).
- Each row: date-time, seat, a plain sentence ("LR 1248 edited", "Challan 13: LR 245 removed", "Wasuli LR 77
  collected ₹500 cash by Ramesh", "System PIN changed", "Backup folder changed to E:\BM"), and on open the changed
  fields old → new with **names, not ids** (firm, station, truck, driver, agent resolved through the masters, money in
  rupees). The sentence is built in the **screen** from the row's fields and `src/strings.ts` (the keeper sends data,
  not wording). Unknown actions show their raw code, never break the page.
- Prints (`print.*`) are listed under their own kind and **hidden by default** (a "Show prints" toggle), so they don't
  flood the list.
- The audit log is append-only (1.3 trigger). Nothing on this page edits or deletes. Index check: add an index on
  `audit_log(at)` **only if** EXPLAIN shows a scan for the default filter — that is migration v3 (never edit v1 / v2);
  run the pre-migration backup as usual.
- Clicking a row opens the record (LR → LR Entry view, memo → the memo, firm → Firm Accounts, wasuli → the Wasuli
  page with that LR found — add a `Jump {to:'wasuli'}`; masters → Masters with the row selected).
- Page in the Admin group, fits 1024 × 768, the list scrolls in its own box, keyboard as the Reports tables.

**PIN coverage proof**
- A test lists every route that checks a PIN and asserts each one writes an audit row on success and on a wrong PIN
  lock-out (5 tries) — wrong single tries are not logged (noise), lock-outs are (`pins.locked`, kind, seat).

**Admin settings (Settings page, each behind the Admin PIN, each audited)**
- **Restore a backup (normal mode):** the 1.4 list + side-by-side preview + restore, now reachable from Settings.
  Refuses while another seat is connected (same rule as updates: seats seen in the last 45 s + the process scan),
  makes a fresh backup first, keeps `booking-before-restore-*`, reloads every open view afterwards (event `['*']`).
- **Backup folder:** pick a folder (main's folder picker) → the keeper checks it is writable, not on the same drive
  as the data root (warn and require a second confirm if it is), then writes `settings.backupDir` and makes a backup
  there at once. The old backups stay where they were.
- **This seat's name:** rename (letters, digits, space, dash; 2–20 chars; unique among seats seen in the last 30
  days) — stored in the seat's own `seat.json` (2.4 convention); history keeps the old name on old rows.
- **Components card:** shown only in a dev build (`npm run dev`), never in the installed app.
- Data-root change stays **out** (installer decision, 1.2/1.6); the Settings card says where it is and that changing
  it is done by the installer.

## Tests
- Database: list order, every filter, paging 100 / 101 / 250, names resolved (incl. a renamed firm: old rows show the
  name as it was in the row, the link opens the current firm), unknown action, prints hidden by default, EXPLAIN for
  the default filter.
- PIN coverage test above.
- Restore from Settings: refused with another seat online, works alone, fresh backup first, before-restore file kept,
  event sent. Backup folder: unwritable refused, same-drive warning, backup written at once. Seat rename rules.
- Pure: the sentence builder for every known action (snapshot), unknown action fallback.

## Out of scope
Changing the data folder, deleting or exporting history, user accounts / logins (seats are the identity),
the load test (4.3).

## Done when
1. All tests pass inside `npm run check`.
2. Real window: History shows the last 7 days with readable sentences; filter by seat, by LR no. 12, by "cancelled";
   open an LR edit row → old → new with names; click it → the LR opens.
3. Make 5 wrong System-PIN tries → a lock-out row appears; change the System PIN → a row appears.
4. Settings: change the backup folder (a backup appears there), rename the seat, restore a backup (with no other seat
   open) — each needs the Admin PIN and shows in History. The Components card is absent in the installed build.
5. `HANDOFF.md` updated; changed files listed with one suggested commit message, the worktree steps (commit and
   confirm before removing — never `--force`), then `git push` and `gh run list --limit 3`.
