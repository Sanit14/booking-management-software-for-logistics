# Session 1.5 — Design system and app shell

## Goal
The app gets its real look: direction A "DM Evolved". Every building block later screens need exists once,
styled, keyboard-ready, and shown together on one **Components** page. The app opens into the real shell
(sidebar + pages) instead of the placeholder. No business data on any page yet.

## Source of truth for the look
`docs/design/A-Dashboard.dc.html`, `A-LREntry.dc.html`, `A-Memo.dc.html` (read their inline styles for exact
colours, sizes and spacing; they can't be opened as pages). Canvas for eyes: https://claude.ai/artifact/SmBSiqn81FBXnxVUwi2SkY
(top row = direction A). DM's look for comparison: `C:\Users\HP\Desktop\dm - auto update\dr-testing\src\index.css`.

## Decided rules for this slice
**Tokens and fonts**
- `src/styles/tokens.css`: every colour, font size, spacing step, radius and shadow as a CSS variable, taken
  from the A mockups. Core: teal-dark `#144D52`, teal `#1D9699`, DM orange `#E66C32` (logo, active-item
  border only), button orange `#C4531B` (anything with white text on orange), orange ink `#B34A15` on tint
  `#FDEEE6`, page bg `#EEF4F3`, input bg `#F3F8F7`, borders `#BFD3D1` / `#D3E2E0`, text `#16323B` / `#4E6B73`,
  ticked/selected tint `#E3F3F2`.
- Fonts bundled locally (the seats are offline): Plus Jakarta Sans (UI) and Inter (inputs, numbers), via
  pinned `@fontsource` packages, only the weights used. Numbers use `font-variant-numeric: tabular-nums`.
- Readability floor from CLAUDE.md is a hard rule: inputs ≥ 17px text / ≥ 44px tall, tables ≥ 15px,
  labels ≥ 14px semibold, nothing below 12px, contrast ≥ 4.5:1, unmistakable focus ring.
- Chrome 108 only: no `color-mix()`, `oklch()`, native CSS nesting. Plain CSS + CSS Modules (one
  `.module.css` per component). No CSS-in-JS, no Tailwind.

**Components** (`src/ui/`, each with its module CSS; data always comes from the caller)
- Button (primary orange, secondary teal, outline, ghost, danger; normal and small) and KeyCap chip ("F4").
- Field: label, input, hint, error, read-only, money input (right-aligned, tabular, ₹ prefix), required mark.
- TypeAhead: list under the field, ↑/↓ move, Enter picks, Esc closes, typed text kept if nothing picked,
  optional last row (e.g. "Walk-in — keep typing"). Matching/ranking is a pure function with tests.
- Table: teal header, zebra rows, numeric columns right-aligned, sticky header in a scroll box, totals row,
  ticked-row tint, empty state.
- Chip: Booked, Loaded, Cancelled, ToPay, Paid, Charges, Pending, Saved (DM's pill colours, darker text
  where needed for contrast).
- Card, StatCard (big number, label, counts only), PageHeader (teal banner, title, right-side actions).
- Toasts: success, error, warning, info; bottom-right inside the window; success/info auto-hide after
  4 s, errors stay until closed; one `useToast()`.
- Dialog (confirm / cancel, Esc closes, focus trapped and returned) and PinDialog (dots + keyboard digits,
  wrong PIN shakes and clears; PIN checking itself is NOT here — the caller decides).
- `useEnterToNext`: inside a form, Enter moves to the next field (Shift+Tab goes back natively); Enter on
  the last field or a button does what that button does. Pure "next field" logic tested.
- Icons: `lucide-react` (pinned), as DM uses.

**App shell**
- Sidebar as in mockup A: logo badge (teal square, orange truck, inline SVG), "Booking Manager",
  "Sundeep Freight Movers". MAIN: Dashboard, LR Entry, Loading Memo. ADMIN: Firm Accounts, Wasuli, Reports,
  Masters, Settings. Active item = orange text, orange tint, orange left border. Count badges supported
  (no real counts yet).
- Orange **Quick LR** button visible on every page (does nothing yet; opens a "coming in 2.4" toast).
- Every page exists as an empty shell with its PageHeader and an empty state. Switching pages is a small
  state switch in the app (no router library; the app has no URLs to share).
- Footer/status area: keeper dot (connected / safe mode / not running), seat, last backup time — replaces
  the 1.1–1.4 status line. The SafeMode screen and Export button from 1.4 are restyled with the new
  components (same behaviour).
- **Components page** (reachable from Settings, and opened directly with `npm run dev -- --components`):
  every component in every state on 1024×768 frames.
- All text stays in `src/strings.ts`.

## Tests
- Pure logic with `node:test`: TypeAhead matching/ranking (prefix before contains, case and spacing
  ignored via the same rules as `nameKey`, walk-in row always last), `useEnterToNext` next-field logic.
- `npm run check` stays green; no new database code.

## Out of scope
Real data on any page, Quick LR form and user shortcuts (2.4), dashboard counts (2.5), printing (3.3),
window maximise / kiosk decision (1.6, on hardware), dark mode.

## Done when
1. `npm run dev` opens into the shell: sidebar, Dashboard page, Quick LR button, keeper status, looking like
   mockup A (owner compares against the canvas).
2. Every page in the sidebar opens its empty shell.
3. The Components page shows every component and state; at 1024×768 nothing is clipped.
4. Keyboard only, on the Components page: Tab/Shift+Tab reach every control with a visible focus ring;
   Enter moves between form fields; TypeAhead works with ↑/↓/Enter/Esc; Dialog and PinDialog close with Esc
   and return focus.
5. Safe mode (delete `booking.db` with the keeper stopped) shows the restyled restore screen and still restores.
6. Fonts load with the network off (they are bundled).
7. `HANDOFF.md` updated; changed files listed with one suggested commit message and the worktree merge steps.
