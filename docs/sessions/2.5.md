# Session 2.5 — Dashboard counts and global search

## Goal
The app's home page: at a glance, how today is going (counts only, **never money**), and one search box that
finds any LR, firm, truck or station in under 100 ms. Closes Phase 2.

Look first: mockup `docs/design/A-Dashboard.dc.html` (its amounts were removed on purpose); DM's
`src/components/GlobalSearch.tsx` and `src/pages/Dashboard.tsx` for behaviour only (Ctrl+K overlay).

## Decided rules for this slice
**Keeper**
- `dashboard.summary(date)` — one SQL statement of subqueries over indexed columns, no amounts:
  LRs today (booked / loaded / cancelled), quantity today, pending to load (all booked LRs, any date) and the
  oldest pending LR date, memos today, trucks out today, stations with pending LRs.
  Memo-based counts are 0 until memos exist (3.1); keep the SQL ready.
- `dashboard.pendingByStation()` — `GROUP BY to_station_id WHERE status='booked'`: station, LR count, quantity;
  most LRs first; `LIMIT 20`.
- `search(text)` — fixed lookups, each `LIMIT 5`, newest/closest first, in one call:
  LR number (exact, this year then last year), firm (prefix on `name_key`, then contains), truck (contains on
  `number_key`), station (prefix), and later challan number (exact; empty until 3.1).
  Text under 1 character → empty. Never a generic query. Every lookup uses an index (`EXPLAIN QUERY PLAN`
  checked in a test).
- `KEEPER_VERSION` bump.

**Screen**
- Dashboard page (F1): four StatCards (LRs today · Pending to load · Memos today · Trucks out today) with
  their small sub-lines (e.g. "Booked 17 · Loaded 25", "Oldest 20-10"), "Pending by station" card with a
  "Make loading memo" link (goes to the Loading Memo page; it says "coming in 3.1" until then), and a
  "Recent LRs" card (last 8 LRs today: number, consignee, To, status chip — no amounts).
- Counts refresh only on change events for `lrs` / `memos` (2.2 hook). No timers.
- Sidebar count badges: LR Entry = LRs today, Loading Memo = pending to load.
- **Global search:** a big search box at the top of the Dashboard and a **Ctrl+K** overlay from any page
  (add `globalSearch` to the per-seat keys from 2.4, default Ctrl+K). Results grouped (LR · Firm · Truck ·
  Station), ↑/↓ + Enter opens:
  - LR → LR Entry with that LR open in view mode (2.3);
  - Firm / Truck / Station → Masters on that tab with the row selected;
  - Challan (from 3.1) → the memo.
  Typing waits 120 ms after the last key before searching; only the newest answer is shown.
- All text in `src/strings.ts`. Fits 1024×768 with no page scroll.

## Tests
- Database: summary counts on a seeded day (booked, loaded, cancelled excluded from LRs-today totals as in
  2.3, pending across days, oldest pending); pending by station order and limit; search per kind incl. LR
  number of last year, prefix before contains, limits, empty text; no amount column in any dashboard answer;
  every query uses an index.
- Speed (real keeper): search on 3 000 firms and 20 000 LRs under 100 ms; summary under 50 ms.
- Pure: grouping and keyboard movement in the results list.

## Out of scope
Memo creation (3.1); amounts anywhere on the dashboard (owner's rule); reports (4.1).

## Done when
1. All tests pass inside `npm run check`.
2. Dashboard shows the right counts for a day of test LRs, and they move by themselves when another seat saves
   or cancels an LR.
3. Ctrl+K from Masters → type an LR number → Enter → that LR opens in view mode; type part of a firm name →
   Enter → Masters, Firms tab, that firm selected. Truck by "1234", station by its first letters.
4. No ₹ amount anywhere on the Dashboard.
5. `HANDOFF.md` updated; changed files listed with one suggested commit message and the worktree steps
   (commit and confirm before removing — never `--force`).
