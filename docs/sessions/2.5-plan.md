# Session 2.5 plan — Dashboard counts and global search

Card: `docs/sessions/2.5.md` (on `main`, commit 54a04d9; this worktree was cut one commit earlier, so the card is not in
the worktree yet — merge `main` or copy it at hand-off).

## Primary goal
A clerk presses F1 and sees how today is going (counts, never money), and presses Ctrl+K anywhere, types a few
letters of an LR number, firm, truck or station, and lands on it in under a second.

## Phase 0 — what exists (read, nothing to build)
**How this serves the goal:** it fixes what we reuse, so nothing is re-invented.
- Indexes already there (schema v1, **no migration needed**): `lrs_by_date(lr_date)`, `lrs_pending(status, to_station_id, lr_date)`,
  `UNIQUE(lr_year, lr_no)`, `memos_by_date`, `UNIQUE(name_key)` on stations/firms, `UNIQUE(number_key)` on trucks.
- Reuse: `localDate`, `isDate` (`keeper/lrRules.ts`), `nameKey` (`names.ts`), `truckKey` (`masterRules.ts`), `useKeeperData`
  (events), `StatCard` / `Card` / `Table` / `Chip` / `Dialog`, `Sidebar` `badges` prop (exists, unused), `isoToDisplay`,
  the per-seat keys (`shared/keys.ts`, `sanitize` gives a missing action its default), `lrs.get(id)`, `guarded()` in LR Entry.
- Route plumbing is always: `shared/keeper.ts` type → `keeper/server.ts` (`known` + branch) → `electron/keeperBridge.ts`
  IPC handler → `electron/preload.ts`. The keeper `*.dbtest.ts` run under Electron-as-node (own SQLite), `*.test.ts` under Node.

## Phase 1 — Keeper queries (test first)
**How this serves the goal:** the counts and the search answers come from SQL, fast, with no money in them.
- New `keeper/dashboard.ts`: `summary(db, date|null)` = ONE statement of subqueries (booked / loaded / cancelled today, qty today
  [cancelled out], pending = all booked, pending qty, oldest pending date, stations with pending, memos today, trucks out today
  [memo SQL ready, 0 until 3.1]); `pendingByStation(db)` = GROUP BY `to_station_id`, most LRs first then name, `LIMIT 20`;
  `recentLrs(db)` = last 8 LRs of today (number, consignee, To, status; no amounts).
- New `keeper/search.ts`: `search(db, text)` → `{ lrs, firms, trucks, stations }`, each `LIMIT 5`. Text trimmed, < 1 char → empty, capped at 100.
  LR: all-digits → exact `(lr_year, lr_no)` this year then last year. Firm: prefix on `name_key` (index range), then contains (`instr`).
  Truck: contains on `number_key` (typed text through `truckKey`). Station: prefix. `instr` not LIKE, so `%` / `_` need no escaping.
- Tests (`dashboard.dbtest.ts`, `search.dbtest.ts`): seeded day → counts (cancelled out of LRs-today, pending across days,
  oldest pending, memo counts with a seeded memo); pending order + limit 20; search per kind, last-year LR, prefix before
  contains, limit 5, empty / 1-char text, inactive rows flagged; **no key named like money in any answer**; `EXPLAIN QUERY PLAN`
  on every statement; speed at 3 000 firms + 20 000 LRs (search < 100 ms, summary < 50 ms).

## Phase 2 — Wiring
**How this serves the goal:** the screen can reach the new answers, and old keepers are replaced so no seat talks to one without them.
- `shared/keeper.ts`: `DashboardSummary`, `PendingStation`, `RecentLr`, `SearchAnswer` (+ row types), `KeeperApi.dashboard.{summary,pendingByStation,recentLrs}`, `KeeperApi.search`; `KEEPER_VERSION` 10.
- `keeper/server.ts`: routes `/dashboard/summary|pending-by-station|recent`, `/search` (read-only: no event, nothing logged — the text may be a name).
  `electron/keeperBridge.ts` + `electron/preload.ts`: four named handlers.
- Test in `server.test.ts` (real keeper): routes answer, summary moves after an LR save and a cancel, no money key over HTTP, `keeper.log` holds no search text.

## Phase 3 — Keys and pure screen logic (test first)
**How this serves the goal:** Ctrl+K is a per-seat key like the others, and the results list behaves correctly before any UI exists.
- `shared/keys.ts`: action `globalSearch`, default `Ctrl+K`; `strings.keys.actions.globalSearch`; update `keymap.test.ts` (defaults list).
- New `src/logic/searchResults.ts` (+ test): `flatten(answer)` → rows in display order with group headings (LR · Firm · Truck · Station, empty groups skipped),
  `move(index, step, count)` for ↑/↓ (wraps; -1 when empty), `jumpOf(row)` → `{to:'lr', id}` | `{to:'master', kind, id}`.

## Phase 4 — Dashboard page and sidebar badges
**How this serves the goal:** F1 shows today at a glance.
- New `src/dashboard/DashboardPage.tsx` + `.module.css`: search box, four StatCards (LRs today · Pending to load · Memos today · Trucks out today,
  sub-lines "Booked n · Loaded n", "Oldest dd-mm-yyyy"), "Pending by station" card (with "+ n more stations" when over 20) and the
  "Make loading memo" button → Loading Memo page, Recent LRs card (status chips). Lists scroll inside their cards; no page scroll at 1024×768.
- `App.tsx`: ONE `useKeeperData(summary, ['lrs','memos'])` (null until the shell is up, like LR Entry's `fresh`); it feeds the Dashboard and
  `Sidebar badges` (LR Entry = LRs today, Loading Memo = pending). Pending-by-station and recent LRs refetch in the page on `lrs`/`stations`. No timers.
- All text in `strings.dashboard`.

## Phase 5 — Global search UI and jumps
**How this serves the goal:** typing finds the thing and opens it.
- New `src/search/GlobalSearch.tsx` (+ css): input, 120 ms wait after the last key, only the newest answer shown (ticket counter), grouped results,
  ↑/↓ + Enter or click picks. Used inline on the Dashboard (results float under the box) and in a Ctrl+K `Dialog` (`wide`; Esc closes, focus goes back to the opener).
- `App.tsx`: Ctrl+K → overlay (ignored while another dialog is open, like the other keys); a pick sets `jump {to, id, n}` and calls `go(page)`
  (so the unsaved-edit "Discard changes?" guard still applies). The page clears the jump once it has used it, so coming back later does not repeat it.
- `LrEntryPage`: a jump opens that LR read-only via `lrs.get(id)` through the existing `guarded()` ("Discard what is on the form?"). A last-year LR works (by id).
- `MastersPage`: a jump switches to that tab, clears the search text, selects the row (shows it in the form, ticks it) once the lists are loaded; turns on "Show inactive" for an inactive row.
- `strings.search`.

## Interpretations to confirm (the card is silent or loose)
1. Speed test runs on a 20 000-LR database **in-process** (dbtest, real SQLite file); the system-Node keeper test cannot seed it. The HTTP route test uses small data.
2. Firm and truck "contains" read the small masters tables (no index can serve it); LR, firm-prefix and station lookups are index SEARCHes; no statement scans `lrs` or `memos`. `EXPLAIN` test says exactly that.
3. A third Dashboard call `recentLrs` (the card needs the data, names no call).
4. Search finds inactive firms / trucks / stations (flagged), Masters then shows inactive rows.
5. Ctrl+K opens the overlay on every page, the Dashboard included.
6. "Coming in 3.1" = a small muted line by the "Make loading memo" button; the button still goes to the Loading Memo page.
7. After midnight the counts stay on the old day until the next change event (no timers, rule 9).
8. An old seat `keys.json` that already uses Ctrl+K for another action falls back to the defaults (the existing "two actions on one key" rule).
