# Session 2.4 — Quick LR, user shortcuts, drafts and LR-page layout

## Goal
A clerk can book an LR from **any** page without losing their place, set their own keys, never lose a
half-typed LR, and see more of the day's list on LR Entry.

## Decided rules for this slice
**Drafts (one per seat, per form)**
- The LR Entry form and the Quick LR form each keep their typed values while the clerk is on another page.
  Kept in the screen's memory only (not the database, not across an app restart): a draft is not a booking.
- When an LR is saved or "New LR" is pressed, its draft is cleared. An LR opened for **edit** is not kept as
  a draft (leaving the page asks "Discard changes?").

**Quick LR**
- The orange **Quick LR** button (and its key, default **F2**) opens a dialog over any page with the same LR
  form, same Enter flow, same keeper calls (`lrs.preview`, `lrs.create`), same validation and walk-in rules.
  No new keeper code.
- Save (F4) → toast "LR 1248 saved", the dialog stays open and clears for the next one; Esc closes it and the
  clerk is back exactly where they were (focus returned).
- The dialog fits 1024×768 (no list inside it; a line "Last saved: LR 1248 · Consignee · ₹ total").

**User shortcuts (per seat, like DM)**
- Settings → "Keyboard shortcuts" card: every action from `src/keymap.ts` with its key; click "Change", press
  the new key (F1–F12, or Ctrl/Alt + a letter or digit). A key already used by another action is refused
  ("Already used by: …"). "Reset to defaults" button.
- Stored per seat in the seat's own config file next to `seat.json` (main process), not in the database:
  each clerk's keys stay on their seat. Loaded at start; changes apply at once.
- Actions in this session: Save LR (F4), New LR (Esc), Quick LR (F2), Go to LR Entry (F3),
  Go to Loading Memo (F5), Go to Dashboard (F1), Focus the LR-no. search (Ctrl+F). Reserved and refused:
  Alt+F4, Ctrl+W, Ctrl+R, Tab, Enter.
- Key hints on buttons and in tooltips read the seat's current keys.

**LR Entry layout (owner to confirm; this is the default if no feedback)**
- Goal: the day's list shows **at least 8 rows** at 1024×768 with nothing clipped.
- Make the form compact: fields in 3–4 columns per row as in mockup A, a smaller page header, the amounts box
  on the same row as the charges. Keep the 17 px input / 44 px height floor.
- If 8 rows still don't fit, put the list **beside** the form (mockup A) with fewer columns
  (LR, Consignee, To, Qty, Amount, Status).
- The action strip (Edit / Cancel / History) for an opened LR goes into the form header, not a separate row.

## Tests
- Pure: shortcut validation (allowed keys, reserved keys, duplicates), key-event → action matching,
  draft keep/clear rules.
- `npm run check` green; no keeper changes expected (bump nothing unless a route changes).

## Out of scope
Dashboard counts and global search (2.5), a separate Saved LRs page, printing (3.3).

## Done when
1. All tests pass inside `npm run check`.
2. From Masters, press F2 → Quick LR → save two LRs → Esc → back on Masters with the cursor where it was;
   both LRs are in LR Entry's list.
3. Type half an LR on LR Entry, go to Settings and back → the typed values are still there.
4. Change Quick LR to Ctrl+Q in Settings → it works at once; try to give it F4 → refused; Reset to defaults.
   A second seat's keys are unchanged.
5. LR Entry at 1024×768 shows at least 8 list rows (measure), with an LR open and with errors showing.
6. `HANDOFF.md` updated; changed files listed with one suggested commit message and the worktree steps
   (commit and confirm before removing — never `--force`).
