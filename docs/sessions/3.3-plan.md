# Session 3.3 — plan (printing: loading memo A4, LR A5 landscape, PDF, company settings)

Status: **waiting for approval — no code written.** Card: `docs/sessions/3.3.md`.

## Primary goal
A clerk opens a saved memo (or a just-saved LR), presses **Print** or **Save PDF**, and gets the paper layout from the spec
on the client's A4 printer — the 60-LR memo over several pages, the LR on A5 landscape — without any other page of the app changing.

## Phase 0 — Discovery (done, nothing to build)
**How this serves the goal:** it fixes what exists, so the plan copies patterns instead of inventing them.
- Electron 22 API, read from `node_modules/electron/electron.d.ts` (main folder): `webContents.print(options, cb)` with `silent`, `margins.marginType`,
  `landscape`, `pageSize`, `header`/`footer`; `webContents.printToPDF(options): Promise<Buffer>` with `pageSize`, `landscape`, `margins`,
  `printBackground`, `preferCSSPageSize`, `displayHeaderFooter`. Chrome 108 has **no** `@page` margin boxes / `counter(page)`, so "Page n of m" must be
  written by our own page splitting (the card's pure test says the same). No Electron API for page numbers in `print()`.
- Patterns to copy: named route + `bridge.call` (`keeperBridge.ts`), Admin-PIN settings write (`lrs.setDefaults`, `LrDefaultsCard.tsx`),
  `writeAudit` inside a transaction, `strings.result(code)`, `Dialog`/`PinDialog`, unknown audit actions are already ignored by both histories
  (`lrs.history`, `memos.history`), `lrAmounts`/`FROZEN_SQL`/`memos.get` (frozen totals + `differs`), `memoTesting.ts` helpers.
- Anti-patterns: no global `@media print`; no keeper route named by the screen; no money maths in a template; no `Math.round` outside `money.ts`;
  no `shell.openExternal`/network in the print window; no `git commit`.
- Gaps found: the worktree has **no `node_modules`** (`npm install` + `npm run postinstall`, about 5 min, first check about 7 min). HANDOFF still says 3.2 is
  uncommitted, but `git log` shows 3.2 committed and the card added: HANDOFF is fixed in the hand-off step.

## Phase 1 — Keeper: print data, company, audit (tests first)
**How this serves the goal:** the paper must carry the frozen totals and the exact LR amounts, formatted once, in the one process that owns money.
- `keeper/money.ts`: `inr(paise)` = Indian grouping with two decimals (`1234567` → `12,345.67`). Test first (`money.test.ts`).
- `keeper/print.ts` (`makePrint(pins, memos)`): `company(db)` (settings `company_name|address|phone|gstin`, name defaults to "Sundeep Freight Movers"),
  `setCompany(db, seat, input, adminPin)` (Admin PIN, trim, name 1–100, other lines ≤ 100, one audit row `settings.company` before/after, event `settings`),
  `memo(db, id)` → `PrintMemo` (header from `memos.get`, rows by `(lr_year, lr_no)` with Sr, LR no, consignor, consignee, destination, particular, qty, to pay, paid — all
  strings already formatted; **frozen** totals; `status`, `differs`), `lr(db, id)` → `PrintLr` (own SQL; amounts from `lrAmounts`: freight with To pay / Paid, the four charge
  lines, tax % and tax, total; `status`), `done(db, seat, kind, id, how)` → one audit row `print.memo` / `print.lr` (`how` = print | pdf), only after a print or a saved file.
- Routes `/print/memo|lr|done|company|set-company`; `KEEPER_VERSION` 13; no migration. Types in `shared/keeper.ts` (`PrintMemo`, `PrintLr`, `PrintCompany`,
  `KeeperApi.print.company/setCompany` only — memo/lr/done are reachable by main, not by the screen); result code `company-invalid` (+ wording in `strings.result`).
- Tests: `print.dbtest.ts` — memo answer = frozen totals while rows show LRs now; order by LR number (also across a year); `differs` and `cancelled` flags (cancelled memo: no rows);
  LR amounts equal `lrAmounts` for To pay and Paid, with and without tax; cancelled LR; missing id; audit row per print and none when the id is missing;
  company default, Admin PIN needed (wrong PIN writes nothing), trim and limits, audit before/after. `server.test.ts` — routes answer, `done` writes and publishes no event,
  `set-company` publishes `settings`, no PIN or company text in `keeper.log`.
- Verify: `npm run check` green.

## Phase 2 — Templates in `print/` (pure, no Electron)
**How this serves the goal:** the layout from the spec, split into fixed A4 pages so "Page n of m", the repeated header row and totals-only-on-the-last-page are exact.
- New top-level folder `print/` added to `tsconfig.node.json` `include`: `template.ts` (`esc()`, the document shell and the one stylesheet: black on white, serif, ≥ 9 pt, `@page` size with margin 0,
  page boxes with 10 mm padding, `page-break-after` between pages only, no `overflow:hidden`), `memo.ts` (`paginate(n)` + `memoHtml`), `lr.ts` (`lrHtml`, A5 landscape, two columns:
  parties/goods left, amounts right, signature line). Wording in `strings.print` (rule 11). Cancelled → large outlined "CANCELLED" mark. `differs` → the small line from the card.
- Memo page: one line per LR (nowrap, long names end in "…"), about 30 rows on page 1 and 40 after (numbers fixed by the real PDF test, phase 3), room for the totals row on the last page.
- Tests (`node --test`): `paginate` (0, 1, boundary, boundary+1, 60, 500 rows: sizes sum to n, last page ≥ 1 row, totals once), header row on every page, `Page n of m`, escaping of `<`, `&`, `"`, `'` in
  names and company lines, golden HTML snapshots of memo-1, memo-60, memo-cancelled, lr, lr-cancelled (`print/snapshots/*.html`, LF-normalised, `UPDATE_SNAPSHOTS=1` rewrites),
  and a test that **no file under `src/` contains `@media print`** (Done-when 5).

## Phase 3 — Electron print engine and the real-PDF test
**How this serves the goal:** this is the part that reaches the Windows print dialog and the PDF file; it must not touch the app's window or styles.
- `shared/print.ts` (`PrintApi`: `memo(id, how)`, `lr(id, how)`; `how` = `print` | `pdf`; answer `KeeperResult<{ file?: string }>`, `cancelled` for a closed dialog), `electron/print.ts`
  (`initPrint(bridge)`): fetch data through `bridge.call`, build the HTML, hidden `BrowserWindow` (`show:false`, no preload, `sandbox`, `javascript:false`, own session that cancels every request
  except `data:`), `loadURL(data:…)`; **Print** = `webContents.print({ silent:false, pageSize, landscape, margins:{ marginType:'none' } })`, **Save PDF** = `printToPDF` + `dialog.showSaveDialog`
  (`Challan-13-2026.pdf`, `LR-1248-2026.pdf`), then `/print/done`. Wired in `main.ts`, `preload.ts` (`window.bm.print`), `global.d.ts`.
- Real test: `electron/print.electrontest.ts` run by `scripts/test-electron.cjs` (spawns the Electron binary as an app, not as Node) as the last step of `npm run check`; renders a 1-LR memo, a 60-LR memo,
  a memo at each page boundary, a cancelled memo, an LR and a cancelled LR through the same code as the app → PDF size > 0 and `/Type /Page` count equals the number of pages the template made
  (an overflow would add a page and fail). `package.json` `build.files` leaves out `*.electrontest.js`.
- Verify: `npm run check` green; one real run of `npm run dev` on this PC printing to "Microsoft Print to PDF" to see that the Windows dialog opens in front.

## Decisions I need you to confirm (defaults I will take if you just say go)
1. **₹ on paper:** amounts are plain Indian-grouped numbers with two decimals (`12,345.67`) and "₹" appears in the column headings, because a Windows 7 PC without the rupee-sign update draws "₹" as a box.
   The card says "₹ with Indian grouping"; say so if you want the sign in every cell.
2. **One line per LR:** long names are cut with "…" on paper so the page count is exact (about 30 rows on page 1, 40 on the next). Wrapping would make the page numbers unreliable.
3. **Rows ordered by LR number** (year, number) as the card says; the screens use (date, number).
4. **Audit after success:** the `print.*` row is written when the print was sent / the file saved, not when the button is pressed, so a closed Windows dialog leaves no row.
5. **New step in `npm run check`:** the real-PDF test starts Electron for a few seconds (slow the first time in a fresh worktree).
