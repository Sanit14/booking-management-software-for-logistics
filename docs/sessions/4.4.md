# Session 4.4 — Full audit, fixes, clean-up (last code session before the pilot)

## Goal
Before real bookings go in, run every audit scan over the whole app, fix what they find (starting with the two keeper
stalls the 4.3 bench found), remove dead code and unused dependencies, and leave the repo in a state the owner can
maintain. No new features.

## First: the known stalls from 4.3 (fix before scanning)
- **`/backups/list`** runs `quick_check` on every backup **on the keeper's thread** (16 s for one 458 MB backup; minutes
  with 48 retained) — every seat's save and health ping stalls, a watchdog can declare the keeper dead.
- **`/restore/preview`** — two `quick_check`s on the thread, 21 s.
- **Fix rule (decided):** list backups **without** checking them (name, time, size, read-only open for counts only if it
  is fast — measure; otherwise counts come with the preview); run every `quick_check` in the child process
  (`verifyBackup` / `keeper/verifyChild.ts` is the pattern). The preview awaits the child; the keeper keeps serving.
  A restore apply re-checks the chosen file in the child before swapping.
- **Clean stop takes 8–14 s** on a big file (its backup): make sure the installer and the updater wait long enough for
  the keeper's pid (measure; raise the wait if needed, never kill a keeper mid-backup).
- Prove with the 4.3 file (`C:\bmload` or a new `npm run seed:load`): open Settings → Restore a backup… while a second
  client saves LRs and pings `/health` every second — no save or ping over 1 s; add the rows to the bench.

## Then: the scans (`/scan all`, plus the extras below) — fix every High and Medium
1. `.claude/commands/scan.md` scans: **db, calc, logic, print, perf, failure, migration, state** (CLAUDE.md rules).
2. **security** (`security-and-hardening`): CSP and window settings in production, IPC allowlist (no generic channel),
   keeper bound to 127.0.0.1 only, PIN handling, no secrets / test PINs / `BM_*` test hooks able to weaken a
   production keeper (e.g. `BM_PIN_LOCK_MS` — refuse or ignore when packaged), updater signature path, paths from the
   screen never trusted.
3. **ponytail-audit** (whole repo): dead code, unused exports, duplicate helpers, speculative options; delete.
4. **dependencies:** `npm ls`, unused packages removed, versions pinned exactly, `npm audit` reviewed (Electron 22
   advisories stay accepted — note any new one).
5. **strings:** every UI text in `src/strings.ts`; no Hinglish / placeholder / "TODO" text visible to a clerk.
6. **docs:** `HANDOFF.md` shortened to what is still true (history moved to `docs/handoff-archive.md`), README for the
   owner: how to run, test, release, restore, where the key lives (never the key itself).

## Rules
- Each finding: severity, file:line, rule, fix — in `docs/audit-4.4.md`. High / Medium fixed in this session with a test
  that fails before the fix; Low fixed if small, otherwise listed for after launch.
- No behaviour change a clerk would notice, except the stall fixes. Anything that would change behaviour → ask the owner.
- `KEEPER_VERSION` bump if keeper code changes; a migration only if a scan finds a schema defect (never edit v1–v4).
- Version **0.3.1** for the release after this session.

## Out of scope
New features, the open owner decisions (report name filter, LR total for To pay vs Paid, Agent page, booking wasuli
rules), the pilot (4.5).

## Done when
1. `npm run check` alone, exit 0, three times in a row.
2. The stall test passes on the 3-year file: no save or ping over 1 s while backups are listed, previewed and restored;
   the bench (idle PC) still all PASS, with the new rows.
3. `docs/audit-4.4.md` lists every scan's findings; no High / Medium left open.
4. Dead code and unused dependencies removed; `npm ls` clean; owner README written.
5. `HANDOFF.md` short and current; changed files listed with one suggested commit message, the worktree steps (commit
   and confirm before removing — never `--force`), then `git push`, `gh run list --limit 3`, and the release steps for
   0.3.1 from the main folder.
