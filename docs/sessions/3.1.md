# Session 3.1 — Loading Memo (create)

## Goal
The loading clerk filters the pending LRs, ticks the ones going on one truck, fills truck, driver, truck hire
and loading hamali, and saves a **loading memo (challan)**. The ticked LRs become Loaded, the memo gets the next
challan number of its year, its totals are frozen, and **an LR can never be on two memos**, even when two seats
save at the same moment. Opens Phase 3.

Look first: mockup `docs/design/A-Memo.dc.html`; DM's `src/pages/ChallanHeader.tsx` (header fields) for
behaviour only.

## First: fix the flaky test from 2.4
`keeper/pins.dbtest.ts` "what is stored is a salted hash…" asserts the random hex hash does not contain
"1111"/"2222", which can happen by chance. Assert the stored value is not the PIN and does not parse as it

## Decided rules for this slice
**Keeper**
- `memos.pending(filters, cursor)` — booked LRs only (`status='booked'`), filters: booked-from / to date,
  To station, consignor, consignee (firm id or walk-in text); ordered by `lr_date, lr_no`; keyset paging,
  100 per page; returns the rows plus, for the whole filter, `COUNT` and `SUM(qty)` from SQL.
- `memos.create(header, lrIds, uid)` — **one `IMMEDIATE` transaction**:
  1. validate header: memo date (today unless changed with the System PIN, no future), truck (active truck
     master), driver (active driver master), From station (default = booking station), To station (required,
     the delivering station chosen for this memo), truck hire and loading hamali (money ≥ 0, may be 0),
     at least one LR, at most 500;
  2. challan number = `nextNumber('challan', memo_date)`;
  3. insert the memo;
  4. **claim:** `UPDATE lrs SET status='loaded', memo_id=:memo, version=version+1, updated_at, seat
     WHERE id IN (:ids) AND status='booked'`; if rows changed < ticked count → **roll back everything** (no number
     used) and answer `memo-conflict` with the LRs that were taken, each with its current memo's challan number
     and truck ("LR 245 was just loaded on challan 12 · MH 29 BE 1234");
  5. **freeze totals** onto the memo from its LRs, in SQL: LR count, quantity, to pay, paid, charges,
     service tax (same definitions as `lrAmounts`);
  6. audit row `memos.create` (memo id, challan no, LR ids); commit; event `['memos','lrs']`.
- Same `uid` twice → returns the first memo (safe retry), as for LRs.
- `memos.get(id)` (header, frozen totals, its LRs) and `memos.byDate(date)` (that day's memos, newest first,
  `LIMIT 200`) — enough to show "saved" and today's list; editing memos is 3.2.
- Search (2.5) gains **challan number** (exact, this year then last); a pick opens the memo (read-only view
  on the Loading Memo page). Dashboard memo counts now show real numbers.
- Truck hire and loading hamali live on the memo only (not split across LRs).
- `KEEPER_VERSION` bump. **No migration** expected (schema v1 has the memo columns); if one is needed, add
  version 2, never edit version 1.

**Screen — Loading Memo page (F5), 1024×768, no page scroll**
- Top: filter bar — Booked from / to (default: oldest pending … today), To station (TypeAhead), Consignor,
  Consignee, "Clear filters". Filters apply as you change them.
- Left: pending LR table with tick boxes (LR, Date, Consignor, Consignee, To, Qty, To pay, Paid); Space ticks
  the row with focus, Ctrl+A ticks all **shown** rows, Ctrl+Shift+A unticks all; ticked rows tinted
  (`#E3F3F2`); "Load more" at the end when more than 100 match. Ticks survive changing filters (a ticked LR
  stays ticked even if the filter hides it; the panel counts it).
- Right: memo panel — Challan "Next: n" (grey, real number after save), date, Truck (TypeAhead, trucks),
  Driver (TypeAhead, drivers), From, To (defaults to the To-station filter if one is set), Truck hire ₹,
  Loading hamali ₹, and **live totals of the ticked LRs** (LRs, Qty, To pay, Paid — from the keeper, the
  screen does no money math), then **"Create memo (n LRs)"** with the Save key (F4 by default; per-seat keys
  from 2.4). Enter walks the panel fields; the note "If another seat loads a ticked LR first, saving stops
  and names it."
- Memo date unlock with the System PIN (same as LR date).
- On `memo-conflict`: dialog naming each taken LR; those LRs are unticked and the list refreshes; nothing saved.
- After save: toast "Challan 13 saved · 11 LRs", the panel clears (keeps date and From), ticks clear,
  the LRs vanish from the pending list on **every** seat (events). A "Today's memos" strip under the panel:
  challan, truck, To, LR count.
- The Dashboard's "Make loading memo" opens this page with the To-station filter set when it came from a
  station row.
- All text in `src/strings.ts`.

## Tests
- Database: pending filters (each one, combined), order, paging cursor, totals for the whole filter; create
  happy path (status, memo_id, frozen totals = sum of `lrAmounts` of its LRs, challan number per year, audit,
  event); refusals write nothing and use no number (no LRs, inactive truck/driver, missing To, negative money,
  future date, date without PIN); **claim guard**: an LR already loaded → whole save rolled back, answer names
  it; cancelled LR can't be ticked in; same uid twice → one memo; 500-LR memo works, 501 refused.
- Real keeper: **two seats create memos with an overlapping LR at the same moment** → exactly one succeeds, the
  other gets `memo-conflict` naming the LR and the winning challan; no LR on two memos; challan numbers have no
  gap. Speed: a 100-LR memo saves under 300 ms; `pending` over 20 000 LRs under 100 ms.
- Search finds a challan number; Dashboard counts memos and trucks out.

## Out of scope
Viewing/editing/cancelling a saved memo, removing or moving an LR, the "differs from its LRs" flag (3.2);
printing (3.3); Wasuli (3.4).
