# Session 4.1 — Reports

## Goal
One Reports page with the six booking reports from the spec plus the wasuli report, each for a chosen period,
with totals, drill-down to the LR or memo, and Print / Save PDF. Every figure comes from SQL in the keeper, and
**the same period gives the same totals in every report**. Opens Phase 4.

Look first (behaviour only): DM `src/pages/Reports.tsx`, `src/components/GenericReportPrint.tsx`,
`src/components/ReportPager.tsx`; this app's Firm Accounts (3.5: period presets, keyset paging, print of a long
table, the SQL twin of `lrAmounts`).

## Decided rules for this slice
**Reports (columns = the spec's v1 defaults; the owner may change them after seeing them)**
| Report | One row per | Columns |
| --- | --- | --- |
| Date-wise | LR date | Date, LRs, Qty, To pay, Paid, Charges, Service tax, Total |
| Station-wise | To station (route = station) | Station, LRs, Qty, To pay, Paid, Wasuli |
| Consignor-wise | Consignor (firm, or walk-in name as booked) | Consignor, Station, LRs, Qty, To pay, Paid, Wasuli |
| Consignee-wise | Consignee (same) | Consignee, Station, LRs, Qty, To pay, Paid, Wasuli |
| Truck-wise | Memo | Memo date, Challan, Truck, To station, LRs, To pay, Paid, Truck hire, Loading hamali |
| Firm-wise | Firm (masters only) | Firm, LRs as consignor, LRs as consignee, Qty, To pay, Paid |
| Wasuli | Agent | Agent, Assigned (count, amount), Collected in period (count, amount), Unassigned pool (count, amount) |

- Period = **LR date** for every LR-based report (as Firm Accounts); **memo date** for Truck-wise;
  **collected date** for the collected part of Wasuli. Cancelled LRs and cancelled memos are left out.
  Truck-wise money = the memo's **frozen** totals (what was printed), with a Differs mark when they no longer
  match (3.2).
- Filters per report where they make sense: To station, firm / party text, truck, agent.
- Each row is clickable: Date → that day's LRs in LR Entry; Station / party / firm → a detail list of its LRs in
  the period (LR no., date, other party, To, Qty, amounts) → an LR opens in LR Entry view; Truck-wise row →
  the memo (3.2); a Firm-wise row → Firm Accounts for that firm and period.

**Keeper (reads only; `KEEPER_VERSION` bump; no migration)**
- One named route per report: `reports.dateWise | stationWise | partyWise(role) | truckWise | firmWise | wasuli`
  plus `reports.lrs(kind, key, from, to, cursor)` for the drill-down list. `GROUP BY` and totals in SQL, keyset
  paging 100 rows, every query on an index (EXPLAIN test). Amounts from the same SQL twin of `lrAmounts` as
  3.1 / 3.5 (reuse it; if it now lives in three files, move it to one keeper module first).
- `print.report(kind, query)` for the print engine of 3.3 (A4 portrait, landscape only if a report has more than
  9 columns; header row and "Page n of m" on every sheet; totals on the last; at most 1,000 rows per printout
  as for statements).

**Screen — Reports page (Admin group)**
- Left: the list of reports. Right: period picker (Today, This month, Last month, This year, Custom; default
  This month — the same presets as Firm Accounts), the report's filters, the table with Load more, the totals
  strip, Print and Save PDF.
- Keyboard: ↑/↓ in the report list, Enter opens; inside a report the table is one Tab stop, Enter opens a row.
- Money is shown here (the no-money rule is the Dashboard's only). Fits 1024×768; the table scrolls in its box.
- All text in `src/strings.ts`.

## Tests
- Database, one seeded period with booked, loaded and cancelled LRs, walk-ins, two years, memos (one
  differing, one cancelled), wasuli in every state:
  - each report's rows and totals by hand-checked numbers;
  - **cross-report agreement:** for the same period, the grand totals of Date-wise = Station-wise =
    Consignor-wise = Consignee-wise (LRs, Qty, To pay, Paid), and Firm-wise + walk-ins = the same;
  - period edges (inclusive, across 1 January), filters, paging 100 / 101, cancelled left out, frozen vs current
    on Truck-wise, wasuli by collected date;
  - EXPLAIN: no scan of `lrs`, `memos` or `wasuli`; speed over 20,000 LRs: every report's first page < 100 ms.
- Print: pagination and a real PDF of a 60-row report (same harness as 3.3 / 3.5).

## Out of scope
Changing report columns from the screen, Excel export, charts on reports, the settings / history page (4.2).

## Done when
1. All tests pass inside `npm run check`.
2. Real window (installed 0.2.0 build or `npm run dev`): each report for This month shows rows and totals; the
   four LR-based reports agree on the grand totals; drill-down opens the LR / memo / firm account.
3. Print / Save PDF of a report with 60+ rows → 2+ sheets, header repeated, totals on the last.
4. `HANDOFF.md` updated; changed files listed with one suggested commit message, the worktree steps (commit and
   confirm before removing — never `--force`), then `git push` and `gh run list --limit 3`.
