# Session 2.3 — View, edit and cancel an LR

## Goal
Mistakes happen at the counter. A clerk can open any saved LR, and — with the System PIN — correct it or cancel
it. Every change is recorded with who, when, and what changed, and every other seat sees it at once.

## Decided rules for this slice
**Opening an LR**
- On LR Entry, choosing a row in the day list (click, or ↑/↓ + Enter) opens that LR in the form in **view mode**:
  every box read-only, the LR number shown, buttons **Edit**, **Cancel LR** (or **Restore** if cancelled),
  **New LR** (back to an empty form; also Esc).
- A date box above the list shows another day's LRs (no PIN needed to look). "Today" button returns.
- An "LR no." search box: type a number → opens that LR of the current year (or says not found).

**Edit (System PIN)**
- Edit asks the System PIN once; the form becomes editable with the same Enter flow, validation, walk-in
  rules, charges behaviour and live preview as a new LR. Save = F4 / button.
- `lrs.update(id, version, input, pin)` — one transaction: PIN check → stale `version` refused (returns the
  current LR, screen shows "Changed on another seat, reloaded") → validate → update → `version + 1` →
  audit row with **before and after** (only changed fields) → commit → event `['lrs']`.
- The LR number never changes. The date may change only within the same year (the number belongs to that
  year's series); a different year is refused with a clear message.
- A **Loaded** LR (on a memo) can be edited with the PIN. Its memo keeps its frozen totals; the "differs from
  its LRs" flag comes with memos (3.2). Nothing extra here.

**Cancel / Restore (System PIN)**
- Cancel needs the System PIN and a **reason** (required, free text). `lrs.cancel(id, version, reason, pin)` →
  status `cancelled`, audit row with the reason, event.
- A Loaded LR can't be cancelled: "LR 245 is on memo 1263 — remove it from the memo first" (memo removal is 3.2).
- The cancelled LR keeps its number (numbers are never reused), stays in the list greyed with a
  **Cancelled** chip, and is **left out of the day totals**.
- Restore (System PIN, a cancelled LR only) → back to `booked`, audit row, event.

**History**
- View mode shows a small "History" panel for that LR from the audit log: created / edited / cancelled /
  restored, seat, time, and for edits the changed fields (old → new; money shown in rupees, firm/station
  names not ids). `lrs.history(id)` reads it; newest first; at most 50 entries.

`KEEPER_VERSION` bump. All text in `src/strings.ts`.

## Tests
- Database: edit happy path (changed fields only in the audit); stale version refused with current row;
  wrong PIN writes nothing; validation refusals write nothing; date change within the year allowed, across a
  year refused; edit of a loaded LR allowed; cancel needs a reason and the PIN; cancel of a loaded LR refused;
  cancelled excluded from `byDate` totals but listed; restore; number never reused after cancel; history
  order and content; one event per committed change, none on refusal.
- Real keeper: two seats edit the same LR — the second gets the stale answer, nothing lost.

## Out of scope
Removing an LR from a memo (3.2), printing / reprinting (3.3), Quick LR and configurable keys (2.4),
layout changes to LR Entry (decided after the owner's 50-LR test, then done in 2.4).

## Done when
1. All tests pass inside `npm run check`.
2. Real window: open an LR from the list → view mode → Edit (PIN) → change To pay and the consignee → F4 →
   the list, totals and History show the change; a second seat's list updates by itself.
3. Cancel with a reason → greyed row, Cancelled chip, totals drop; Restore brings it back.
4. Try to edit the same LR from two seats → the second is told it changed and sees the new values.
5. `HANDOFF.md` updated; changed files listed with one suggested commit message and the worktree steps
   (commit and confirm before removing — never `--force`).
