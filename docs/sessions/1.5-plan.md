# Session 1.5 — plan (design system and app shell)

## Primary goal
The owner runs `npm run dev` and sees the real Booking Manager: sidebar, pages, Quick LR, keeper status, in the
direction-A look, plus one Components page proving every building block works with the keyboard alone.

## Phase 0 — what the code and mockups say (read, not assumed)
- `src/` today: `App.tsx` (status line + Export button), `SafeMode.tsx` (unstyled), `strings.ts`, `main.tsx`.
  No CSS, no CSS Modules, no fonts, no icon lib. `window.bm` exists only inside Electron.
- `tsconfig.web.json` has `types: []` (no node types); `tsconfig.node.json` only includes `electron keeper shared`,
  so `node --test` today never sees anything in `src/`. Pure `src/ui` logic needs its own include there.
- `npm run dev` = `concurrently ... "electron . --dev"`; extra args after `--` do not reach electron unless
  `concurrently -P` + `{@}` is used. Main loads `DEV_URL`; `will-navigate` only checks origin, so a `#components` hash is safe.
- Mockup values (inline styles in `docs/design/A-*.dc.html`): sidebar 204px, nav item 42px/15px, header banner
  84px (Dashboard) / 52px (forms), input 46px/17px Inter, table head 36–38px/13px, rows 38–52px/15px, chips 24px/13px
  with 6px dot, KeyCap 22px/12px, toast 44px, listbox option 44px. Card says tables ≥ 15px and labels ≥ 14px, so
  mockup's 13px table heads and chip text go to 14px / 13px→**14px** (floor: nothing below 12px; 13px only for hints).
- DM pill colours (`index.css` `--success/--warning/--danger/--info/--purple`): several fail 4.5:1 as text
  (success `#16a34a`, danger `#dc2626`). I will darken only those and check every pair with a throwaway script.
- Packages (checked on npm, ≥ 2 weeks old except lucide's newest): `@fontsource/inter 5.3.0`,
  `@fontsource/plus-jakarta-sans 5.3.0`, `lucide-react 1.59.0` — all `-D --save-exact` like the other tooling.
  Inter also needs `latin-ext` for `₹` (U+20B9).

## Slices (each ends with `npm run check`)
1. **Plumbing + tokens** — install packages, tokens, fonts, global focus ring, tsconfig/eslint changes.
2. **Pure logic, red then green** — the two test files above, then `typeAhead.ts`, `nextField.ts`.
3. **Static blocks** — Button, KeyCap, Chip, Card/StatCard/PageHeader, Field/MoneyInput, Table.
4. **Interactive blocks** — TypeAhead, Toast, Dialog/PinDialog (native `<dialog>.showModal()`: Chrome 108 gives
   focus trap, Esc and focus return for free), `useEnterToNext`.
5. **Shell** — Sidebar (+badges), Quick LR → info toast "coming in 2.4", page switch by `useState` (no router),
   eight empty pages, StatusBox (keeper dot, seat, last backup) in the sidebar foot, restyled SafeMode, Export button
   moves to the Settings page, `--components` flag, Settings → Components page link.
6. **Components page** — every component and state in sections that each fit a 1024×768 frame.

## Decisions I am making (shout if wrong)
- Status area = bottom of the sidebar (where mockup A has the seat box). Long keeper errors / "starting" / safe mode
  take over the whole window as a plain panel, as today — the shell shows only when the keeper is connected.
- TypeAhead: first match is highlighted; Enter picks it; ↓ reaches the "Walk-in — keep typing" row; Enter on it,
  Esc, or leaving the field keeps the typed text. After a pick Enter also moves to the next field.
- PinDialog: Enter submits (PIN length is not known here), digits only, max 8, wrong → shake + clear.
- Fonts: latin (+ latin-ext for Inter), weights actually used only. Devanagari falls back to the system font.
- Sidebar/dates in the mockup (date, "Keys:" line) are not built; no business data anywhere.
