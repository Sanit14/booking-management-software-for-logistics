# Session 2.2 — plan (change events + LR Entry)

Status: approved by the owner ("Go"), built in worktree claude/session-2-2.

## Primary goal
A booking clerk types an LR from the keyboard alone, presses F4, and within a second the LR has its number and every
seat's list and totals show it — without anyone touching the other seats' screens.

## Phase 0 — what already exists (read this session; nothing outside the repo is needed)
**How this serves the goal:** the LR save must copy the patterns that already work, so it is as safe as a master save.
- Schema v1 already has `lrs` (all money columns, `uid UNIQUE`, `UNIQUE(lr_year, lr_no)`, `CHECK` to-pay XOR paid, `status`), `counters`, `audit_log`, `settings`. **No migration.**
- `keeper/money.ts`: `parseRupees`, `taxPaise`, `chargesFor(rule, qty)` (hamali per dag × qty), `lrAmounts`. `keeper/numbering.ts` `nextNumber(db,'lr',date)` (throws outside a transaction). `keeper/audit.ts` `writeAudit`. `keeper/pins.ts` `verify(db,'system'|'admin',pin)`.
- Seeded `settings.chargeRule_option1|option2|blank` (JSON, paise).
- `keeper/masters.ts` `create()` runs its own `db.transaction`, so it nests (savepoint) inside the LR transaction: walk-in "Add to firms" reuses it, similar-name rule included.
- `keeper/server.ts`: `known` POST routes, `ok/refuse/sendResult`, `seat`, `state !== 'ready'` gate. `electron/keeperBridge.ts` `call()` + one `ipcMain.handle` per route; `preload.ts` one function per route; `shared/keeper.ts` `KeeperApi`.
- Screen: `Table` (totals row, `maxHeight`), `TypeAhead` (portal list, walk-in row), `Field` (`money`), `useEnterToNext`, `PinDialog`, `Dialog`, `Chip` (booked/loaded), `useToast`, `Page`. Masters page is the pattern for load / newest-answer-wins / form remount.
- DM charges behaviour read (`ChallanDetail.tsx` 343–390): option fills bhada / insurance / delivery / hamali; hamali = per-dag × qty; `manualFields` stops auto-fill for a field typed by hand. **DM clears `manualFields` when the option changes; the card says keep them — card wins.**
- Mockup `A-LREntry.dc.html`: the form is on top, "Today's LRs" table + totals strip under it, in one 788 px column.

Anti-patterns: money maths or tax in the screen; a generic route; a number issued outside the save's transaction; polling timers; hard-coded F4 outside the one key-map constant; editing migration v1; Node > 16.17 / CSS > Chrome 108.

## Phase 1 — change events (card Part 1)
**How this serves the goal:** this is what makes the other seat's list move by itself.
- Keeper: `keeper/events.ts` `makeEvents()` (set of open responses; `publish(tables, ids?)` writes `data: {...}\n\n`). `GET /events` (SSE, host check, 127.0.0.1) in `server.ts`. Publish **after** the transaction returned ok, in the route: masters write → `[kind]`; pins change → `['settings']`; LR create → `['lrs']` (+`['firms']` for a walk-in saved); restore → all tables. Refused / rolled-back = nothing sent.
- `keeper/client.ts` `subscribeEvents(port, opts, onChange)`: Node http, reconnects with 1 s → 5 s back-off, calls `onChange` for each event and (after a *re*connect) once with all tables so views refetch what they missed. Tested without Electron.
- Main: `initKeeperBridge` calls it once per seat and forwards to every window on `keeper:changed`. Preload `keeper.onChanged(cb)` → unsubscribe. `shared/keeper.ts`: `ChangeTable`, `KeeperChange`.
- Screen: `src/useKeeperData.ts` — `useKeeperData(fetcher, tables)` → `{data, reload}`; loads on mount, keeps only the newest answer, refetches only when an event names one of its tables. No timers.
- Masters page and the LR pick lists move to it (own `load()` after a save goes; the event does it).

## Phase 2 — LR rules in the keeper (test first)
**How this serves the goal:** number, validation and money are decided only here, inside one transaction.
- `money.ts`: `parsePercent("5" | "2.5") → bp` (≤ 2 decimals, 0–100) + tests.
- `keeper/lrRules.ts` (pure): `cleanLr(input, today)` → clean values or `fields: {name: code}` (required, amount, qty, both-money, same-station, future-date, …). `today` = the keeper PC's local date (not UTC).
- `keeper/lrs.ts` `makeLrs(pins, masters)`:
  - `defaults(db, date?)` → today, booking station, default option, default tax bp, expected next number (peek, not issued).
  - `preview(db, input)` → no write: `lrAmounts` + charge defaults for option and quantity (+ the field errors so far).
  - `create(db, seat, input)` → one transaction: same `uid` → return the first LR (`again: true`); validate; stations / firms exist and active; date ≠ today needs the System PIN (wrong PIN writes nothing); walk-in "Add to firms" via `masters.create` (exists / similar → whole save rolled back, refusal names the party; resend with `confirmSimilar`); `nextNumber('lr', lr_date)`; insert; audit `lrs.create`; return the saved LR with amounts.
  - `byDate(db, date?)` → that day's LRs newest first by `lr_no`, `LIMIT 1000`, totals from SQL (`COUNT`, `SUM(qty)`, `SUM(topay)`, `SUM(paid)`, booked / loaded counts; cancelled excluded).
  - `settings.setLrDefaults(db, seat, …, adminPin)` → booking station, default option, default tax %; audit row.
- Routes `/lrs/defaults|preview|create|by-date`, `/settings/lr-defaults`, `/settings/set-lr-defaults`; bridge + preload; `KEEPER_VERSION` 8.

## Phase 3 — LR Entry screen
**How this serves the goal:** keyboard-only flow, F4, no mouse, fits 1024×768.
- `src/lrEntry/LrEntryPage.tsx` + `LrForm.tsx` + css. Layout = the mockup: form on top in 4 rows, "Today's LRs" box under it filling the rest and scrolling inside itself, totals strip + Booked / Loaded chips. (The card says "left / right"; at 1024 px a 9-column table at 15 px does not fit beside the form.)
- Field order as the card: Consignor → Consignee → To station → Particular → Quantity → To pay → Paid → Charge option → Godown bhada → Godown insurance → Delivery charges → Hamali → Wasuli → Service tax % → Save. Date (read-only, "Change date" → System PIN) and From station skipped by Enter, reachable by click / Shift+Tab (new `data-skip-enter` flag in `useEnterToNext` / `nextField`, pure + tested).
- Consignor / consignee: `TypeAhead` over active firms with the walk-in row; walk-in shows "Add to firms" (unticked).
- Charges: option select fills the four charge fields from the keeper's defaults; a field typed by hand is kept on quantity / option change; clearing it hands it back to auto (`src/logic/chargeFill.ts`, pure + tested). Live amounts box from `lrs.preview`; the screen shows, never adds.
- Save = F4 / button / Enter on the last field; disabled while in flight; success toast "LR 1248 saved"; form clears but keeps date, From station, option, tax %; focus to Consignor. Last-used option per seat in `localStorage`. F4 from `src/keymap.ts` (one constant).
- LR number: "New" + expected next in grey.
- `src/logic/rupees.ts`: display-only formatting of paise (list, totals, field text); no arithmetic on money.
- Settings page: new "LR defaults" card (booking station, default option, default tax %), Admin PIN to save.
- All text in `src/strings.ts`; `App.tsx` renders the page for `lrEntry`; sidebar Quick LR stays "coming in 2.4".

## Calls I made where the card was silent or conflicted (confirm or change)
1. Layout: stacked as in the mockup, not left / right.
2. Manual charge values survive an option change (card) although DM resets them.
3. "Today" is the keeper PC's local date; the screen sends no date unless the clerk changed it, so a form left open past midnight still saves as today.
4. After "Change date", the System PIN stays in the screen's memory only while the changed date is in use, and is sent with each save (the keeper checks it every time).
5. A walk-in "Add to firms" that matches an existing firm is refused with the existing name shown on the field (pick it from the list); a similar name opens the same confirm dialog as Masters.
6. Totals and counts leave out cancelled LRs.
7. Where to build: this session's worktree folder is empty (2.1's was merged and removed). Recommended: a fresh worktree `claude/session-2-2` from `main` (needs ~6 min `npm install` + `postinstall`); alternative is building straight in the main folder.
