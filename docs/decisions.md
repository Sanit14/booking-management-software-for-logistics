# Decisions

One line per decision, newest at the bottom. Details live in the Spec and Build Plan docs (links in CLAUDE.md).

- 2026-10-22 · Booking Manager is fully standalone from DM: own data, own install, no link.
- 2026-10-22 · Fresh start: no old data imported; the client enters master data only.
- 2026-10-22 · Volume ~300 LRs/day, several NComputing seats, Windows 7 host, 1024×768.
- 2026-10-22 · Masters: firm, station, truck, driver. Route = station (no route master). Agent page deferred.
- 2026-10-22 · LR: one particular + quantity per LR. Walk-in consignor/consignee allowed, can be saved to master.
- 2026-10-22 · LR charges follow DM's charges (cartage) rule: Option 1 / Option 2 / Blank from Settings fill godown bhada, godown insurance, delivery charges, hamali (per dag × qty, flat, none); all editable; to pay XOR paid.
- 2026-10-22 · Service tax % set per LR, on freight only (to pay or paid), printed on the LR.
- 2026-10-22 · LR and challan numbers are running series that reset every 1 January.
- 2026-10-22 · LR edit / cancel / move off a memo needs the System PIN.
- 2026-10-22 · Loading memo = filter pending LRs, tick, assign truck + driver (masters); from = loading station, to = delivering station chosen for the memo.
- 2026-10-22 · Memo totals are frozen at save; later LR edits flag the memo until a PIN-gated Recalculate.
- 2026-10-22 · One LR can only be on one memo; claim guard refuses and names the LR and truck.
- 2026-10-22 · Wasuli page v1 = copy of DM's; booking-side rules decided later.
- 2026-10-22 · Reports v1: date, station, consignor, consignee, truck, firm — default columns in the Spec.
- 2026-10-22 · Same printer as DM; memo on A4.
- 2026-10-22 · Pages: Dashboard (global search + count cards, no money), LR Entry, Loading Memo, Quick LR on every page; Admin: Firm Accounts, Wasuli, Reports, Masters, Settings.
- 2026-10-22 · UI direction A "DM Evolved": DM teal #144D52/#1D9699 + orange; buttons with white text use #C4531B; Plus Jakarta Sans + Inter; bigger type.
- 2026-10-22 · Shortcuts are user-configurable, as in DM.
- 2026-10-22 · Stack: Electron 22.3.27, React 19 + TS, Vite (chrome108), plain CSS + CSS Modules, keeper process + better-sqlite3 (WAL), node:test.
- 2026-10-22 · Keeper port 47715, data root C:\BookingManagerData, backups D:\BookingManagerBackups.
- 2026-10-22 · Owner does all git commits and pushes; GitHub repo created after the first session/app test.
- 2026-10-23 · Tooling pins (dev machine only): TypeScript 5.9.3 (typescript-eslint rejects ≥ 6.1), Vite 7.3.7 + plugin-react 5.2.0, ESLint 9.39.5, `@types/node` 16.18.126 so tsc rejects Node APIs newer than 16.17; all devDependencies, exact versions, `.npmrc` legacy-peer-deps.
- 2026-10-23 · Electron 22 npm-audit advisories accepted (fix needs Electron 41, no Win7); app is offline and loads no remote content.
- 2026-10-23 · Keeper = Electron exe run as plain Node (`ELECTRON_RUN_AS_NODE=1`), detached, binds 127.0.0.1:47715 before touching the database; a second keeper exits 0.
- 2026-10-23 · Main checks the data root (refusal rules) before spawning the keeper; the keeper trusts its argument. The screen gets error codes; all wording lives in `src/strings.ts`.
- 2026-10-23 · A running keeper older than `KEEPER_VERSION` is shut down and replaced; one on a different data root or another program on the port is an error, never "connected".
- 2026-10-23 · Blank-database guard: marker per data root in `%ProgramData%\BookingManager`; marker + missing or 0-byte `booking.db` = safe mode, no new file.
- 2026-10-23 · Keeper tests spawn the keeper as Electron-as-node (rebuilt better-sqlite3 loads only there); pure logic never imports it. `npm run check` wipes and recompiles `dist-electron` before `node --test`.
- 2026-10-23 · `better-sqlite3` 12.11.1 is rebuilt for Electron 22.3.27 by `postinstall` (`@electron/rebuild` 4.2.0, works on dev Node 20.19; needs VS Build Tools and a short path).
- 2026-10-23 · Keeper client opens a fresh connection per request (`agent: false`); seat name = Windows user name, sent as `X-BM-Seat`.
- 2026-10-24 · Schema v1 lives in `keeper/migrations.ts`: ordered migrations, one transaction each with its `schema_version` row; a shipped migration is never edited; a database newer than the keeper is refused. `KEEPER_VERSION` 2.
- 2026-10-24 · Charge options live in `settings` as `chargeRule_option1|option2|blank` (JSON in paise, DM's CartageRule shape); only hamali depends on quantity, godown bhada/insurance/delivery are flat per LR.
- 2026-10-24 · `parseRupees` is strict (Western or Indian comma grouping, at most 2 decimals, anything else is an error); `taxPaise` is the only tax code, round half up; money functions refuse non-integer or negative paise.
- 2026-10-24 · `nextNumber` takes the year from the record's own date, must run inside the saving transaction, and a rolled-back save does not burn a number; `writeAudit` likewise needs a transaction, and `audit_log` refuses UPDATE and DELETE by trigger.
- 2026-10-24 · `lrs.uid` / `memos.uid` are caller-made TEXT UNIQUE; `audit_log.entity_id` is TEXT; `firms.station_id` is nullable; memo money/count columns are CHECK ≥ 0.
- 2026-10-24 · Blank-database guard also compares business-row counts: the marker stores `businessRows` (written on open and on clean stop); marker > 0 and the opened database has 0 → safe mode `marker-with-no-rows`, nothing migrated or written.
- 2026-10-24 · All schema v1 tables are `STRICT`; `lr_date`/`memo_date` are ISO text and `lr_year`/`challan_year` must equal the date's year; `nameKey` is NFC-normalised.
- 2026-10-24 · The guard's `businessRows` baseline is raised every 5 minutes while the keeper runs (never lowered), so a crash on day one cannot leave it at 0.
- 2026-10-24 · Database tests are `*.dbtest.ts`, run by `scripts/test-db.cjs` under Electron-as-node as part of `npm run check`; pure tests stay `*.test.ts` under system Node.
- 2026-10-26 · Backups: SQLite online backup (`db.backup`) into `BM_BACKUP_DIR` → `settings.backupDir` → `D:\BookingManagerBackups`; written as `booking-YYYYMMDD-HHmm.db` (local time) via a `.tmp` name, converted to rollback-journal mode (no -wal/-shm beside it), verified read-only (`quick_check` + row count) and renamed; a failed one is deleted. When: on start if none is dated today (before the keeper reports ready), hourly, on clean stop, before a pending migration on an existing database.
- 2026-10-26 · Retention: newest 48 backup files + the first backup of each of the last 30 days; `booking-before-restore-*` and other files are never listed or pruned.
- 2026-10-26 · A backup that cannot be written (no D: drive...) never stops the keeper or a migration: `health.backup.failing` carries the reason and the status line shows "backups failing: <reason>"; no fallback to C:.
- 2026-10-26 · Start-up runs `quick_check` before migrating; "not a database"/corrupt/`quick_check` ≠ ok → safe mode `damaged` (file untouched); other open errors (permissions, locked) stay fatal.
- 2026-10-26 · Health gains state `starting` (port taken, database being checked/backed up/migrated); the bridge waits it out like "not up yet". `KEEPER_VERSION` 4 (3 was a route rename during review: listing is `POST /backups/list`, not a GET, because it opens every backup).
- 2026-10-26 · Restore: routes exist only in safe mode (`not-in-safe-mode` otherwise); `apply` needs the one-shot token of the latest preview of the same unchanged file; refusals: damaged backup, newer schema, 0-record backup over a live database with records (not over a damaged/missing one), missing/oddly named file. The live file and its `-wal` are first copied (never overwritten) to `booking-before-restore-<time>.db`, then the backup is copied in and the keeper reopens, migrates and rewrites the guard marker.
- 2026-10-26 · Keeper routes now return `KeeperResult` (`{ok, value}` or `{ok:false, code}`); the screen maps codes to wording in `src/strings.ts`. The folder picker for "Export backup to…" lives in main, the keeper only receives the chosen absolute path.
- 2026-10-27 · Session 1.5 design system: tokens in `src/styles/tokens.css`, one `.module.css` per component in `src/ui/`; fonts bundled (Plus Jakarta Sans via `@fontsource`, Inter via hand-written `@font-face` with `unicode-range` because fontsource's subset files have none and latin-ext would otherwise replace latin); icons `lucide-react` 1.59.0; all three pinned exact, devDependencies.
- 2026-10-27 · Pure screen logic (TypeAhead ranking, Enter-to-next) lives in `src/logic/` and is compiled by `tsconfig.node.json` so `node --test` runs it; the TypeAhead match key is a 1-line copy of the keeper's `nameKey` (screen never imports keeper code), a test proves they agree.
- 2026-10-27 · Dialog and PinDialog use the native `<dialog>.showModal()` (focus trap, Esc, focus return come from Chromium 108); children mount only while open. PIN is 4 digits and submits on the 4th digit; checking it is the caller's job (keeper), wrong = shake + clear.
- 2026-10-27 · TypeAhead: first match highlighted, Enter picks and (inside a form with `useEnterToNext`) also moves to the next field; ↓ reaches the optional "Walk-in — keep typing" row; Enter on it, Esc, or leaving keeps the typed text.
- 2026-10-27 · Toasts: success/info hide after 4 s, warning/error stay until closed; one `useToast()`; bottom-right.
- 2026-10-27 · App shell: sidebar + `useState` page switch (no router); keeper status box at the sidebar foot (dot, seat, last backup); "starting", keeper errors and safe mode replace the whole window; Export backup moved to the Settings page; `npm run dev -- --components` (via `concurrently -P`) opens the Components page directly (hash `#components`), also reachable from Settings.
- 2026-10-27 · Readability floor applied over the mockups: table headers, chips, hints inside lists 14px (mockups used 13px); small buttons 38px tall, normal buttons and inputs 46px; status colours darkened where DM's failed 4.5:1 (all pairs checked).
- 2026-10-27 · Session 1.6 packaging: electron-builder 26.15.3 (DM's version), NSIS x64, per-machine, not one-click, `npmRebuild:false` (the `postinstall` rebuild for Electron 22 is the one in the package), output `release\Booking Manager-Setup-<version>.exe`; the package leaves out `*.test.js`, `*.dbtest.js`, `*.map`, `keeper/testing.js` and better-sqlite3's sources/build objects (70 MB instead of 80).
- 2026-10-27 · Installer creates `C:\BookingManagerData`, `%ProgramData%\BookingManager\logs` and (only if D: is a fixed disk) `D:\BookingManagerBackups`, giving the Users group Modify via `icacls *S-1-5-32-545`; it has no uninstall macro, so uninstall never deletes data, backups or ProgramData, and reinstall finds them.
- 2026-10-27 · Keeper survival = seat-side watchdog, no service: main pings `/health` every 15 s (`KEEPER_PING_MS`, the only polling) and recovers on any failed keeper request; `keeperAction()` (pure, `electron/watchdog.ts`) decides ok / wait / start / replace / wrong-app and is also what the launch path uses. A missing or older keeper is started again through the same single-instance launch; the screen gets `reconnecting` then the new status over a `keeper:status` push.
- 2026-10-27 · Window opens maximised (min 1024×768, no kiosk); production CSP drops the dev websocket (build-only Vite plugin); Settings shows app, keeper and schema version, data folder and backup folder (`KeeperHealth.backupDir` added, `KEEPER_VERSION` 5).
- 2026-10-28 · Session 1.7 PINs: Admin PIN (updates, PIN changes) and System PIN (daily LR/memo gates), 4 digits each, set once on first run (Admin then System, each typed twice) with a 12-character recovery code shown once; stored as salted scrypt hashes in `settings` (`pin_admin|pin_system|pin_recovery`), checked only by the keeper; Admin and System PIN must differ (the card was silent). With 4 digits the hash only stops casual reading of the file; the real protection is the lock.
- 2026-10-28 · PIN lock: 5 wrong tries on a PIN kind (admin, system, recovery) lock that kind for 60 s, even for the right PIN; counters live in keeper memory (reset when the keeper restarts); the 5th wrong try already answers `pin-locked`. Every set/change/reset writes an audit row `pins.*` (never a PIN); wrong tries are logged by route, seat and code only. `KEEPER_VERSION` 6; `/health` gains `pid` and `pinsSet`.
- 2026-10-28 · "Other seats online" = seats that sent `X-BM-Seat` to the keeper in the last 45 s (the 15 s pings), own name excluded, plus a Windows process scan of every session (Get-WmiObject, PowerShell 2.0 safe); the keeper's own process is dropped before grouping so a keeper started by another seat cannot hide that seat.
- 2026-10-28 · Updates: electron-updater 6.8.9 (DM's), generic provider on `Sanit14/BookingManager-releases` `releases/latest/download/`; only the Settings buttons talk to the internet; a download must pass electron-updater's SHA-512 and `latest.sig` (Ed25519 over `bookingmanager-update-v1`, version, sha512) against the public key in `electron/updatePublicKey.ts`; install asks the Admin PIN (keeper), refuses if another seat/session is open, makes a verified backup via `/backups/export` into the normal backup folder, stops the keeper and waits for its pid to exit, then `quitAndInstall`; a failure restarts the keeper. The watchdog is paused only between "stop the keeper" and the installer.
- 2026-10-28 · Installer file name has no space (`BookingManager-Setup-<version>.exe`): GitHub turns spaces in asset names into dots, which would break the `latest.yml` URL. Release is local: `npm run update:keygen` once (private key in `BookingManagerKeys` under the owner's profile, never in the repo), `npm run release` = check, dist, sign, print the `gh release create` command; the owner runs it. CI (`.github/workflows/check.yml`) only checks and packages; no secrets.
- 2026-10-28 · Data root `D:` alone is read as the root of drive D (`resolveRoot` in `keeper/dataRoot.ts`), never as "the current folder on D:" that Windows would resolve it to; found by the first CI run (the checkout is on `D:\a\...`, so the 1.1 test `refuses a bare drive` failed there). Test added.
- 2026-10-28 · Masters (2.1): four named keeper routes `/masters/all|create|update|set-active` with a whitelisted `kind` (explicit SQL per kind in `keeper/masters.ts`; not 13 routes, not a generic query). Every write is one transaction with its audit row (`masters.create|update|activate|deactivate`, before/after, never a PIN) and answers with the saved row; `all` returns every station, firm, truck and driver (active and inactive) ordered by name / number. `KEEPER_VERSION` 7.
- 2026-10-28 · Masters PINs: adding and reactivating need no PIN; every edit (including phone or station only) and every deactivation need the System PIN, checked by the keeper before anything is written (a wrong PIN writes nothing). A stale `version` is refused with `master-stale` and the current row; nothing is ever deleted.
- 2026-10-28 · Master duplicate rules: stations and firms by `name_key` (active or not, the existing row comes back so the screen can offer Reactivate); trucks by `number_key` (upper-case, spaces/dots/dashes removed, shown as typed upper-cased); drivers: same name and phone refused, same name alone is `similar`. Firm and driver names that start like another (prefix both ways on `nameKey`) answer `master-similar` and save only when resent with `confirmSimilar`. Edits run the same checks leaving the row itself out. Drivers have no name key column, so their checks compare in the keeper inside the transaction (no migration v2).
- 2026-10-28 · Master values: names are trimmed with inner spaces collapsed, 1-100 characters; phone is optional digits only, up to 15 (spaces, dashes, dots, brackets and a leading + are dropped, anything else is refused); a firm's station must exist and be active (the one it already has stays allowed on edit); tab counts show active rows only.
- 2026-10-28 · The TypeAhead list is drawn through a portal (into the open `<dialog>` if there is one, else the page) with fixed position from the input's box, flipping above when there is no room: no card clips it (fixes the 1.5 known issue for Masters and LR Entry). `Table` gets optional row activation (click or Enter on a focused row, up/down between rows); `Dialog` gets `cancelLabel`; `Chip` gets `inactive`.
- 2026-10-28 · `BM_MARKER_REFRESH_MS` overrides the guard marker's 5-minute refresh (tests only, like `BM_BACKUP_DIR`); the marker end-to-end test promised since 1.3 now exists in `keeper/server.test.ts`.
- 2026-10-28 · Editing a master asks about similar names only when the name changes (an unchanged name that already sits next to a similar one, such as two drivers called Ramesh, is not asked about again); exact duplicates are always refused. A truck number with no letters or digits left once spaces, dots and dashes are removed is refused (empty key). A wrongly typed field answers `master-bad`, it is never dropped.
- 2026-10-28 · The TypeAhead list stays closed while its text is empty (↓ opens it), so Enter on an emptied field moves on instead of picking the first option; `Table` is one Tab stop per list (the picked row, else the first), ↑/↓ walk the rows.
- 2026-10-29 · Change events (2.2): `GET /events` is a server-sent-events stream (127.0.0.1, host check). The keeper publishes `{tables, ids?}` only after a write returned ok (masters, pins and settings, LRs, restore = every table); a refused or rolled-back write, a read, and a retry of an already-saved LR publish nothing. Main keeps one stream per seat (`subscribeEvents` in `keeper/client.ts`, retry 1 s → 5 s) and forwards `keeper:changed`; every (re)connect also announces every table, because events may have been missed. The screen refetches through one hook, `useKeeperData(fetcher, tables)`, newest answer wins; pages no longer reload after their own writes (the event does it). `KEEPER_VERSION` 8, no migration.
- 2026-10-29 · LR save (2.2): routes `/lrs/defaults|preview|create|by-date`, `/settings/set-lr-defaults`. One transaction: validate → stations/firms exist and are active → optional walk-in firms through `masters.create` (nested, so exists/similar roll the whole LR back and name the party) → `nextNumber('lr', date)` → insert → audit `lrs.create`. The same `uid` returns the first LR (`again`), before any validation or PIN. Money, quantity and tax % arrive as the typed text and are parsed only in the keeper; `lrs.preview` returns `lrAmounts` and the charge option's amounts for the quantity, and the screen only formats them (`src/logic/rupees.ts`, display only).
- 2026-10-29 · "Today" is the keeper PC's local date (not UTC); the form sends no date unless the clerk unlocked another one, so a form left open past midnight still saves as today. A date other than today needs the System PIN, checked by the keeper with every save; the screen keeps the PIN in a ref only while the changed date is in use, and falls back to today on a refused PIN. Future dates are refused.
- 2026-10-29 · LR defaults are `settings` keys `bookingStationId`, `defaultChargeOption`, `defaultStaxBp`, changed with the Admin PIN (card in Settings). Until set: no From station, charge option Blank (so no charges appear by surprise), 0% tax. The charge option last used on a seat is remembered in `localStorage` (that Windows user's profile).
- 2026-10-29 · Charge boxes: a box the clerk typed in keeps its text when the quantity or the option changes (the card; DM resets them on an option change); a box emptied and left is handed back to the option. Walk-in "Add to firms" is unticked by default and is a tick box that Enter walks past (Tab, Space). The date and From station are walked past by Enter (`data-skip-enter`) but reachable by Tab/Shift+Tab. F4 is named once in `src/keymap.ts` (2.4 makes keys configurable).
- 2026-10-29 · LR Entry layout follows the mockup (form on top, the day's LRs under it, one 788 px column), not the card's "left/right": a 9-column table at 15 px does not fit beside the form at 1024 px. The list shows about three rows and scrolls inside its own box. `byDate` is `LIMIT 1000` with totals from SQL; cancelled LRs are left out of totals and counts.
- 2026-10-30 · Open / edit / cancel / restore an LR (2.3): named routes `/lrs/get|find|update|cancel|restore|history` (get and find are not on the card: the list row cannot fill the form, and the number search needs find), `KEEPER_VERSION` 9, no migration. Every write is one transaction: System PIN first, then the stale-`version` check (refused with `lr-stale` and the current LR), then the same rules as a new LR (`resolveLr` is shared with `create`), then an UPDATE of only the columns that differ, `version + 1`, one audit row (`lrs.update` before/after of the changed columns only; `lrs.cancel` carries the reason; `lrs.restore`). An edit that changes nothing writes nothing and publishes no event.
- 2026-10-30 · Edit rules (2.3): the LR number never changes; the date may move only within the number's year (`year` field error) and an edit with no date keeps the LR's own date; a cancelled LR cannot be edited (restore it first); a firm or station the LR already has stays allowed after it was deactivated and keeps the name as booked, a new pick must be active; a loaded LR can be edited (its memo keeps its frozen totals). Cancel needs a reason (1-200 characters) and is refused on a loaded LR with the memo's number (`lr-on-memo`); a cancelled number is never reused; cancelled LRs stay listed, greyed with a Cancelled chip, and are left out of the day totals. Restore returns it to booked.
- 2026-10-30 · History (2.3) is read from the audit log (`ORDER BY at DESC, id DESC LIMIT 50`); stations are shown by name, money in paise for the screen to format. It opens as a dialog from a History button, not as a panel: the entry page has no room at 1024×768 and the card puts layout changes after the owner's 50-LR test.
- 2026-10-30 · LR Entry screen (2.3): clicking a list row (or typing its number in the box above the list) opens the LR read-only; Edit asks the System PIN once and the form keeps that PIN in a ref until the save; the cancel call itself checks the PIN (a wrong PIN only shakes the dots). The charge boxes of an opened LR all count as typed by the clerk, so the charge option cannot overwrite a saved amount or a saved 0. The list's own day box (looking needs no PIN) is separate from the PIN-unlocked entry date. A strip above an opened LR carries the buttons, so the list shows about two rows while one is open.
- 2026-10-30 · Keyboard shortcuts (2.4) are per seat and live in `keys.json` next to `seat.json` in the Windows user's userData (main, `electron/seatKeys.ts`), never in the database; the keeper is not involved (no route, `KEEPER_VERSION` stays 9). The rules are one pure file, `src/logic/keymap.ts`, used by the screen and by main: allowed = F1–F12 or Ctrl/Alt + a letter or digit; refused = Alt+F4, Ctrl+W, Ctrl+R, Tab, Enter and (added) Ctrl+C/V/X/A/Z; a key already used says "Already used by: <action>"; Esc is a default for New LR only (it cannot be chosen, Reset to defaults brings it back); a file with a bad entry gets the default for that entry, a file with two actions on one key is replaced by the defaults. Keys are matched by the physical key (`code`), so layout and AltGr do not matter. Seven actions: Save LR F4, New LR Esc, Quick LR F2, Go to LR Entry F3, Loading Memo F5, Dashboard F1, find an LR Ctrl+F.
- 2026-10-30 · Main now imports `src/logic/keymap`, so the packaged app must contain `dist-electron/src/logic/`: the `!dist-electron/src/logic/**` exclusion in `package.json` `build.files` is removed (a few KB of unused test-free JS is shipped).
- 2026-10-30 · Drafts (2.4): a new LR being typed is kept in screen memory (`src/logic/drafts.ts`, slots `lrEntry` and `quick`, state + save uid), written on every change, cleared when the LR is saved, when New LR is pressed, or when another LR is opened after "Discard what is on the form?"; only what the clerk typed counts (From station, option and tax % alone do not). Nothing is kept across an app restart; the PIN-unlocked backdate and its PIN are never kept (the form comes back dated today). An LR opened for edit is never a draft: changing page while editing asks "Discard changes?" (App-level guard; also for the page keys).
- 2026-10-30 · Quick LR (2.4) is the LR form in a wide `Dialog` (F2 / the sidebar button), its own draft slot and its own `defaults`/`masters` data; no new keeper code. A save keeps the dialog open, clears the form and says "Last saved: LR n · consignee · ₹ total"; Esc closes it and the opener gets its focus and its text caret back (`Dialog` remembers the selection of a text box). The form's save/new keys act only when the topmost open dialog is the form's own, so Quick LR over LR Entry saves once, and a PIN dialog swallows them.
- 2026-10-30 · Toasts are drawn inside the topmost open `<dialog>` while one is open (a modal dialog covers everything else; the Popover API is Chrome 114+), and redrawn when a dialog closes: fixes the 1.5 / 2.1 "dialog covers toasts" note.
- 2026-10-30 · LR Entry layout (2.4): no page header on this page; the form card's head row carries "New LR · Next: n" (or the opened LR's number, status and buttons, as the card asked), rows are LR no/Date/Consignor/Consignee, From/To/Particular/Qty/To pay/Paid, charges, tax/amounts/Save; From moved after the parties in the DOM (Enter walks past it anyway); "Add to firms" sits on the label line; the charge labels stay on one line; table rows 32 px / header 34 px on this page only. A box's own error text is no longer drawn under the box (it would push the list below 8 rows): the box turns red, screen readers still read it, and the head says what is wrong in one line (`src/logic/errorSummary.ts`). Measured at 1024×768: 8 full list rows for a new LR, with an LR open and with five errors showing, no page scroll. The card's "list beside the form" fallback was not used (it needs ~700 px of form height in a ~376 px column).
- 2026-10-31 · Dashboard (2.5): named read routes `/dashboard/summary|pending-by-station|recent`, no write, no event, `KEEPER_VERSION` 10, no migration. `summary(date)` is ONE statement of subqueries over indexed columns: "LRs today" = booked + loaded of the day (cancelled counted apart and left out of the quantity), "pending" = every booked LR of any date with its quantity, oldest date and station count, memos / trucks out of the day from saved memos (0 until 3.1, the SQL is ready). `pendingByStation` = GROUP BY To station, most LRs first then name, `LIMIT 20`; `recent` = the newest 8 LRs of today (the card names no call for it). No statement selects an amount, and a test checks no answer carries a money-like key.
- 2026-10-31 · The Dashboard counts and the sidebar badges (LR Entry = LRs today, Loading Memo = pending) come from one `useKeeperData(summary, ['lrs','memos'])` in `App`; the two lists on the page refetch on `lrs` / `stations`. No timers (rule 9), so after midnight the counts stay on the old day until the next change event.
- 2026-10-31 · Search (2.5): `/search` takes the typed text and answers `{lrs, firms, trucks, stations}`, each `LIMIT 5`: LR number exact this year then last year (`UNIQUE(lr_year, lr_no)`), firm prefix on `name_key` (index range, upper bound = key + U+10FFFF) then contains (`instr`, not LIKE, so `%` and `_` are plain), truck contains on `number_key` (the text through `truckKey`), station prefix. Inactive firms, trucks and stations are found and flagged. A contains lookup reads only the small firms / trucks table; every other statement is an index SEARCH and none scans `lrs` or `memos` (EXPLAIN QUERY PLAN test). Nothing about a search is logged. The challan lookup comes with the memo list (3.1).
